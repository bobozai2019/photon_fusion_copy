# 房间、局次与断线续玩

房主进程持有房间、成员及世界的权威状态。一个房间可连续开多局。普通客人的连接寿命、房间成员身份和车辆对象寿命分别管理。

下表描述启用凭票接回的车场大厅。新连接有 8 秒提交加入或接回请求。Godot 原生 `Netcode` 房间离线时立即释放席位，后续按普通加入流程获得席位。[原生 Godot 房间](godot-scene-sync.md#原生节点接入)

| 输入 | 房主与客人应观察到的结果 |
| --- | --- |
| 从 Cocos2d-x、Godot 或 Unity 的 Windows Player 正常启动 | 首屏显示本机 IPv4 和可手填的房间端口。重抽时提供最多三个随机端口，每个都通过 TCP 和 UDP 绑定检查。实际建房时再次绑定 |
| 房主建房，B 在等待阶段加入 | B 占用一个成员席位。房主开局后锁定本局成员 |
| 房主创建房间，或客人输入房主的 IPv4 和端口加入 | 等待页显示端点、房间 ID、席位计数和房主/客人名单。仅房主可以点开始或踢出其他玩家 |
| 等待期间发消息 | 房主依据连接认定发件人并按接收顺序广播。每条最多 512 个 UTF-8 字节，房间保存最近 32 条，新加入客人收到同一记录 |
| 房主在等待期间踢出 B | 房主释放 B 的席位，仍在房间的成员更新名单。B 回到联机首屏，看到被移除提示，可以用原地址和端口重新加入 |
| 全新玩家 C 在游戏中加入 | 拒绝加入，成员和世界保持原状 |
| B 在游戏中掉线 | 保留 B 的身份、业务数据和名额直到本局结束；车辆保持原对象，房主清零持续驾驶输入并继续物理模拟。车辆可能因惯性或碰撞改变位置 |
| B 再连接同一房主、同一房间及同一局 | 验证恢复资格，绑定回原成员与车辆；以房主当前世界状态恢复，恢复完成后继续接收输入。重连期间其他对象的生成、销毁和属性变化也应反映在 B 的世界中 |
| 重复恢复、来自旧连接的包或错误凭证 | 同一成员最多一个有效控制连接；错误请求无法接管车辆，旧包无法修改新会话中的状态或重复触发动作 |
| 房主正常结束本局 | 丢弃本局恢复资格与本局占用的离线名额，保留房间，返回等待并开放新玩家加入。房主可以在原房间开启下一局 |
| 房主主动退出房间或意外失联 | 未配置接班房主的车场房间结束，其余客人收到退出或超时事件。启用备用节点时另走[迁移契约](game-session.md) |

[Core 房间状态机](../../core/session/room.cpp)与[车场世界恢复](../../../examples/yard/shared/match.cpp)分别管理 RoomId、RoundId、PlayerId、ObjectId 和每次连接的会话代次。恢复凭证与成员、房间、局次绑定；由房主保管玩家数据和角色关联，客户端保留重连所需凭证。普通断线恢复从当前权威基线衔接后续增量，恢复时以当前持久状态为准，过去的瞬时 RPC 不会重播。验收需要同时观察 B 的原车辆 ID、当前状态和席位计数，避免“重新生成一辆相似的车”也通过测试。

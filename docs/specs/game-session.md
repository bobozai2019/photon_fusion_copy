# 通用游戏会话

## 同引擎客户端同步

联机只支持同引擎房间。Godot 玩家加入 Godot 房主，Unity 玩家加入 Unity 房主，Cocos2d-x 玩家加入 Cocos2d-x 房主。双方须运行同一游戏，并使用兼容的对象模板、字段和 RPC 定义。验收在两个独立玩家进程中核对同一房间的对象身份、字段值、当前写者、RPC 和对象生命周期。支持票据且席位仍保留的会话允许客人断线后恢复原身份，再接收当前可见对象的权威状态。Godot 原生 `Netcode` 房间在断线时释放席位，玩家可按普通加入流程重新入房。[Godot 原生房间](godot-scene-sync.md#原生节点接入) · [票据与席位](room-rejoin.md)

例如，在 Godot 双端用例中，房主生成一扇门，把开关字段的写权交给另一位 Godot 玩家。客人开门后，房主应读到门已开启。写权交回后，上一代写者迟到的更新应被拒绝。Unity 和 Cocos2d-x 分别用本引擎的两个玩家进程验证同一行为。

## 通用会话接口

玩法通过 `GameSession` 运行房间与对象，通过 `ScriptGame` 接入脚本。Godot 的 `NetcodeGame`、Unity 的 `Netcode.NetcodeGame` 和 Cocos 的 `GameComponent` 接受同一份复制配置。模板和可写字段在开局前登记。未登记为可写的字段仍可复制。机关样例中格子号允许持有人提交，名称由房主设置。

- 每个对象有房内实例号、模板、生成者和当前写者。身份键在地图实例内唯一。地图 0 用于全局对象。地图重载会分配新代次，客户端加载完成时必须带回这一代次。映射以房主为准。父子挂接可以变更，父节点销毁时销毁仍挂接的子节点。
- 外部客户端申请写权时，事务模式请求当前持有人答复。动态模式允许本地先展示预操作。房主按连接身份、可见性、授权代次与冷却裁决；获批后发送预操作，失败时还原公开状态。旁观者可以接收复制数据，房主阻止其写入、生成或触发游戏 RPC。
- 在模型预测模式中，每个对象独立登记输入玩家、模型版本、固定步函数和恢复字段。模型接收中性输入时也推进。房主返回该对象已消费的输入号，客户端从同一步的完整状态重新执行后续输入。状态代次改变时清空旧输入流。
- 网络时间、往返耗时和样本时间以秒为单位。核心按实际经过时间更新网络时钟，序号用于排序。接收者未就绪的地图会阻止相关对象的基线下发。兴趣键分为区域和用户两组，交叉订阅选择最快匹配频率，同时遵守对象配置的上限。进入、离开和销毁优先于普通字段限频。
- 跟踪可靠调用可提供调用令牌，再按令牌与目标读取结果。Received 表示远端有序收包层已接收。Expired 表示发送方在重试上限前未取得确认。双方支持取消时通过控制连接跳过该序号，游戏可继续往同一对象发送后续事件。
- 紧凑快照须由接收方协商。字典仅引用同一接收方已确认的包。没有对应字典时请求刷新，继续沿用对象修订号与原字段验证。每个字段的量化精度由玩法显式配置。
- 原生二维刚体以米、秒和逆时针弧度交换位置、角度、线速度和角速度。代理参与本地碰撞，收到新样本后向权威状态纠偏。传送代次变化时立即同步位姿，睡眠及唤醒写入本地刚体。Cocos 的桌面物理构建使用 Chipmunk 7.0.1。

### 可靠快照的逐连接发送预算

可靠有序 Game 通道按连接计算状态发送预算。TCP provider 与 Core 的待发负载合计接近 64 KiB、最老待发消息达到 50 ms，或连接的有序队列已拒绝新消息时，对该连接暂停生成快照。一次生成最多 27 个 1176 字节的快照包，合计按完整包上限计入 32 KiB 步预算。预算耗尽后从上次扫描位置继续，并按该连接的最新 ACK 计算同一对象的属性差量。已入队消息遵守原投递顺序，控制消息沿用控制队列保留额度。不可靠 Game 通道沿用自身的发送策略。

双方协商授权状态批次后，房主按连接和对象保存尚未提交的最新写入确认。确认和快照共享逐连接、逐步预算。有两包或更多额度时，快照至少留一包，写入确认最多发 8 包。仅剩一包时交替让两类数据先使用额度，空闲份额由另一类使用。客机按写权代次与写入序号更新确认进度。可靠通道成功排队的同一写入修订每隔至少 200 ms 才补发，新修订与未成功排队的写入仍可在下一步发送。

初次校时时，客机保留在途探测号，最长等待 2 秒。收到有效回包后更新时间与 RTT。发送未获接收时可按正常探测间隔继续尝试。

Godot 的 `get_transport_stats()` 返回跨连接汇总。`queued_bytes` 合计 Core 和 provider 待发负载。`snapshot_backpressure_skips` 统计因逐连接发送预算为零而跳过的发送步数，其中 `snapshot_soft_skips` 统计达到软水位的部分。`snapshot_budget_yields` 统计已发部分包并留到后续步继续扫描的次数。`authority_ack_coalesces` 统计尚未提交的写入确认被替换的次数。指标以当前会话为范围。已交给系统 TCP 缓冲区的负载继续受 TCP 顺序约束。

## 玩法接入

Godot 玩法可以直接使用原生 `@rpc` 注解，并在 Replicator 上选择要同步的属性。场景接入路径会生成字段和方法布局。[Godot 声明式接入](godot-scene-sync.md)

合作解谜用地图 1 中的稳定键 100、200 找到两块机关。房主在开局时发布地图资源名、生成机关，客人收到 MapAdded 事件，按资源名完成本地配置后回传该地图代次。框架随后下发机关基线。脚本用局内网络时间判断机关上的同一个截止时间。

| 业务操作 | Godot | Unity | Cocos2d-x |
|---|---|---|---|
| 发布地图、查询资源并确认就绪 | `load_map`、`map_asset`、`loaded` | `LoadMap`、`MapAsset`、`Loaded` | `world().load_map`、`maps`、`loaded` |
| 按稳定键取对象，挂接或释放 | `find_object`、`reparent_object`、`destroy_object` | `FindObject`、`Reparent`、`DestroyObject` | `world().find`、`reparent`、`destroy` |
| 客人按模板申请创建 | 房主调用 `allow_spawn`，客人调用 `request_spawn` | 房主调用 `AllowSpawn`，客人调用 `RequestSpawn` | `world().allow_spawn` 注册工厂，`request_spawn` 返回请求编号 |
| 申请和答复写权，提交字段 | `claim`、`answer`、`submit` | `Claim`、`Answer`、`Submit` | `writers().request`、`ScriptGame::answer`、`submit` |

持有人只能提交模板声明的可写字段。父对象离开本玩家的兴趣范围时，其挂接对象随之隐藏。重新进入后发送当前完整状态和父子身份。PlayerAttached 对象在持有者离房后销毁。MasterClient 对象由协调玩家写入，GameGlobal 也由协调玩家写入。有作者键时以 `(scene, key)` 区分实例。无键实例只能位于默认场景，并独占该模板的 GameGlobal 实例名额。两种形式都禁止指定父对象。[生成约束](../../core/session/world.cpp)

### 注册需要预测的运动模型

新的预测模型通过 C++ 的 `GameSession::prediction()` 注册。为模板提供模型版本、输入字节数、中性输入和 `step(Values&, const Bytes&, Tick)`，单步函数只更新传入的候选状态。房主用 `bind(object, input_player)` 指定预测者；预测者调用 `advance(object, input)` 立即推进，从 `state(object)` 读取预测结果。供单步使用的速度、方向、计数器等均需进入可恢复状态。完整的注册、断包、逆序放行与换权用例见[两个模型的可运行示例](../../tests/core/game_session_test.cpp)。

## 玩家接替房主与本地找房

选择 `MigratingSession` 时，玩法提供可信热备玩家、可监听的地址、端口，以及在新会话上重新登记模板和模型的回调。原房主周期性将成员、地图、对象、授权和已消费输入进度保存到热备。租约失效后，原房主停止工作。当前选举需至少三名参与投票的玩家。热备取得原投票成员过半数的同意后接管；旁观者不计入票数。幸存者按原房间和票据接入新端点，写权代次递增。三人局可从原房主迁至玩家 2，再由玩家 2 主动交给玩家 3。只有已完整到达热备的检查点可以恢复。游戏如需保留道具领取等不可重复事件，应将其结果写入复制状态。飞行中的 RPC 与尚未纳入检查点的动作不具备持久交付保证。

局域网找房通过 `lan_directory` 建立。玩家房主用 `GameSession::advertise` 发布名称、区域、版本、属性和端口，人数与加入策略随房间更新。浏览方用 `search`、`join` 选择端点，连接时由房主再次检查余位与身份。持票重入时以原房间号检索，令 `RoomFilter::require_space=false` 纳入已满的旧房间，随后向该端点出示票据以恢复已预留的席位。回环实验中的身份来源为本地网络。迁移样例在原房主和接任者激活时分别公告各自的监听端口。

见[阶段验收](../../task/fusion-client-parity/验收/记录.md)和[可运行样例](../../../examples/puzzle)。

## 通用玩法接口与版本范围

- 房主生成对象时可以用模板的默认写权策略，也可以单独指定实例模式。同一模板可同时存在可转交和房主专属实例。GameGlobal 使用地图与非零作者键定位，无键的旧式单例仍按模板唯一。写权代次每次交接递增。
- 对象 RPC 注册时选择业务归属或当前写者。写者 RPC 携带授权代次，排队后的实际投递再次检查身份与代次。字节参数可按方法声明上限，旧方法沿用定长契约。RPC 到达与远端玩法处理是两个观测点。
- 允许远程工厂后，客户端可以在返回调用时持有本局 64 位引用，高位是房主分配给本连接的创建命名空间。可将该值保存在玩法状态或作为字节载荷引用对象。获准且实例可见后，ResolveReference 才返回本机可操作的对象号；拒绝、销毁和兴趣范围外返回零。跨局使用必须同时区分房间与局号。显式授权创建者写入的工厂，在接收者具备模型并确认基线后转交写权。
- GDScript 的 register_prediction 和 C# 的 RegisterPrediction 以模板、模型版本、中性输入和单步函数注册。单步仅处理输入和状态，回放时可能重复执行。脚本从预测状态读取即时画面，通过 Reconciled 取得权威模拟步及已消费的输入序号，一次性玩法效果依据确认序号去重。模型版本、字段签名、输入字节数不匹配时拒绝预测流。
- 房主脚本使用 distribute / Distribute 配置对象兴趣，使用 subscribe / Subscribe 设置指定玩家某一类键及发送除数。Inherit 取最近显式配置的祖先分组与频率。父级可见性门槛对独立配置的子对象仍生效。
- Core 会话可通过 `SessionOptions::retain_spatial_writer_interest` 允许已获准的空间对象写者继续收到区外的对象状态。写权归属以当前授权代次为准。该例外使用对象的发送除数，地图、显式对象集合和依赖条件继续生效。迁移端使用相同会话选项时从检查点的授权记录恢复该例外。
- 支持区域限频的房主在首个房间属性基线前发送能力消息。客端协商后可提交每格的正整数发送除数，整组替换自己的区域订阅。兼容旧房主时使用原键集合消息。只修改除数时保持当前可见性，首次基线、隐藏与销毁使用原优先级。
- 发送除数大于 1 的对象按稳定对象 ID 错开普通差量的发送周期。发送步跳过周期边界时，可在当前周期内发送最新状态，仍遵守已有重试保护。全频对象继续在每个发送步可发送。
- change_map / ChangeMap 先验证整张新图的参数，再替换已有地图。地图 0 的持久对象独立存活。异步加载端须在目标代次仍然有效且引擎节点已经挂载时回复 loaded。旧代次不得开启新图的复制。
- 玩家 TTL 以房主单调时钟为基准，局中断开开始计时，到期即释放席位；缺省保留原行为。普通加入与凭票恢复独立。房主可在开局前选择时钟校正模式与 TTL。
- 数个可信玩家可预先配置可监听的热备端点。三人及以上按多数派接替。只剩两名玩家时，在线房主可显式 handoff 并立即冻结业务写入，以控制通道发送最终检查点和交接许可。新房主恢复相同世界和下一任期，可以单人继续。突然失联的两名玩家无法通过本路径各自产生新主。
- 组合使用 Core 房间属性和原生生成模板时，候选端先注册相同的目录、字段布局和模板。检查点保存房间属性及其修订号、创建命名空间和模板生成序号。依赖已终结对象的存活对象继续保留依赖边，在新房主处也不会向观察者发布。这条契约适用于 Core 检查点，Godot 原生 `Netcode` 房间当前只提供开房、加入和退房流程。

### Unity 和 Godot 脚本的接替

开局前，每个参与者在同一个房间角色表上登记候选玩家的监听端点。Unity 用 `NetcodeGame.AddStandby(player, address, port)`，Godot 用 `add_standby`。候选玩家会收到含房间票据的私有检查点，玩法应只登记信任的玩家。通过公开脚本接口注册的写权模板、RPC、预测模型和创建工厂会随会话重建。新房主能用相同的脚本实例提交完整字段。玩法对外部资产、UI 和对象节点的引用由自身管理。

每帧持续调用 `Advance()` 或 `advance()`，直到结束。Unity 通过 `Phase`、`Term`、`IsHost` 判断当前能否写入，Godot 读取 `migration_phase()` 和活动帧的 `term`、`host`。投票、交接期间挂起业务操作。收到 `SessionReplaced`（GDScript 事件 12）时，`epoch` 为新任期，`player` 为新房主。清理旧任期的表现，再处理同帧的地图和对象就绪事件。双人局内，在线房主可显式调用 `Handoff()` 或 `handoff()`。成功受理后旧房主冻结写入并继续泵送，收到最终检查点恢复确认才进入 Ended。若原连接先断，旧房主可进入 Fenced。

### 三维刚体组检查点

将会相互接触或由关节相连的动态体登记在同一个组，使用跨进程稳定的对象号。一个组的同一步状态编码在同一复制对象内，包含步号、对象号列表、休眠位以及每个刚体的位置、单位四元数、线速度和角速度。样例模板容纳四个刚体，单个姿态占 13 个 float。应用方还需保存对应步的输入和会改变物理世界的事件。

回放时创建相同重力、碰撞形状、材质及关节配置的独立物理空间。完整校验组成员和字段后恢复，再按原固定步逐步施加输入。冷启动会丢失求解器接触缓存，验收同时记录相对连续权威模拟的误差和两次独立冷启动之间的误差。模板示例见[组状态](../../../examples/puzzle/island.cfg)。

本轮验收按 60 Hz 步进，先比较第 70 步回放和同一步权威状态的最大位置偏差。`--authority-reset` 在偏差达到 60 mm 时直接恢复整组第 70 步权威状态，同时保留校正前的指标。60 mm 是样例门槛。玩法可以选择自己的容差、发送周期和显示端平滑。两端须约定相同的世界坐标、单位、刚体编号和关节配置。

### 玩法字段、命名调用与挂载组件

字段模板按稳定字段号排列，两端使用同一版本。新增的七类可以同时用于状态和 RPC 参数。配置中的 `vec4` 和 `color` 分别保存四个有限浮点分量，`object_ref` 保存一个本回合的 64 位引用。`bytes`、`vec2_array`、`int_map`、`int_list` 在每个字段末尾声明容量。整数表的键和值均为有符号 32 位，编码按键排序。有序列表保留重复值。协商 word 差量后，集合更新可只携带变更的长度和内容 word。字段格式携带当前完整集合，RPC 参数也按模板编码。[状态布局与差量](property-binding.md#状态布局和差量) · [控制台和两种刚体的模板](../../../examples/puzzle/components.cfg)

对象生成时把挂载的组件与会话、对象号绑定一次。Unity 给 `NetcodeReplica.Fields` 配置目标成员和稳定字段号，Godot 兼容脚本 `replicated_object.gd` 按字段顺序配置相对属性路径；原生节点通过复制配置资源绑定属性，见 [Godot 原生场景接入](godot-scene-sync.md)，Cocos2d-x 给 `ReplicaComponent` 按相同顺序登记成员或访问器。绑定的目标需要与组件一起存活。空字段表可识别 Godot、Unity 原生二维或三维刚体及 Cocos2d-x 二维刚体。Cocos2d-x 的 Bullet 刚体通过 `use_body_3d` 显式绑定。刚体模板沿用位置、旋转、线速度、角速度、休眠、传送代数和玩法阶段七个字段；阈值与采样状态使用相同的网络世界单位，角度阈值使用度。

Unity 对已出现的对象在 `Bind` 时检查字段号、数量和成员类型。首个快照前可以登记绑定，等对象可见时再检查，失败时记录一次错误并解除绑定。Cocos2d-x 在同一引擎步的组件遍历结束后泵送会话、采样和回调。回调中移除组件会结束它本次待执行的工作。

公开引用可在当前可见对象上解析。Unity 使用组件的 `Reference` 和 `game.ResolveGameObject(handle)`，Godot 使用 `replica.reference()` 和 `replica.resolve_node(handle)`，Cocos 使用 `replica->reference()` 和 `network->resolve_node(handle)`。空引用为零。目标隐藏、销毁或尚未绑定时，查询返回空；玩法可以在节点就绪后用同一个引用再次查询。进入新回合应从新基线取得引用。

组件每个引擎更新步检查写权。绑定、换写者、换授权代数后先应用已确认的表现基线。写者发布发生变化的字段；普通客户写者仅能更新授权模板中的字段。观察者把确认的值写回本地成员，刚体在中间步可以继续本地运动。销毁组件会释放本地绑定。

命名方法在两端登记相同的稳定方法号、名称、参数模板、方向、可靠性、作用域及写者限制。调用方用方法名和玩法参数发起调用。接收方先核对签名，再按模板解码并派发到引擎线程。签名含模板版本和布局指纹。零参数用模板号 0。单次参数编码最多 252 字节，注册时按模板最大容量检查。可靠投递回执沿用会话 RPC 的语义，玩法处理成功时可显式回复。新增控制台示例中，客人成功接管后调用 `Report(42, "ready", Vector2(2,-3))`，房主以 `Done()` 确认已处理。见 [GDScript](../../../examples/puzzle/godot/components/components.gd)、[C#](../../../examples/yard/unity/Assets/GameplayComponents.cs) 和 [C++](../../../examples/puzzle/components_cocos.hpp)。

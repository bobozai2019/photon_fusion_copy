## 客户端行为深化

房主统一裁决对象创建，客户端的即时引用与用于快照的 32 位对象号分开。房主按连接发放独立命名空间，并在接替检查点保存高水位。借此保留旧客户端和已有作者键的读法，支持收到创建结果之前传递引用。替代方案是给客人预留可直接用于快照的对象号段；判断差异的实验是创建调用返回后、房主处理之前读取对象字段。目前只有逻辑引用可以立即跨端传递。

房主控制的网络时钟可以用持续单调微调，也可选择 555 公开客户端中观察到的误差分段。样本来源仍是房主回显，上下行不对称会偏移估计。三个引擎的原生刚体各自由本机求解器推进，Forecast 的修正类型、阶段收敛与轨迹误差可以独立验收。求解器的位级一致性和 Photon 的私有编码不作为这两个组件的前提。[原版观测](../../research/fusion/findings/native-runtime.md)

无在线第三方的双人房依靠房主显式退让才可安全移交最终状态。交接期间旧房主永久停止业务写入，即使传输中断也不恢复写权。多任期重新开设监听端点并清除旧选举票与租约。可区分实验为三人强杀后在两人局正常退出，再检查最后一人的任期、席位和最后一笔写入。[本轮验收](../../task/fusion-client-parity/深化状态.md)

同一客机持有许多对象时，房间协议会为每条状态和确认重复编码房间头。沿用 TCP 层的散写只能减少系统调用。Core 通过独立握手为可靠有序连接启用状态与确认合包，仍按对象校验代次和序号。包内保留记录顺序及原有字段编码。用同一 TCP 模块运行新旧房间和混连场次，分别统计外层消息、对象记录和字节数，可区分 Core 合包与底层套接字批处理的收益。[线上格式](../specs/object-authority.md) · [基线与 A/B](../../task/godot-platform/验收/属性同步性能.md#房主接收客机持权对象上行)

Fusion Core 的公开兴趣契约允许所有者跨出区域后继续收到自身对象更新。本项目按房主是否启用会话选项，为已有写权的客端保留空间兴趣。手工筛选、地图门槛和依赖条件仍沿用原规则。写权移交时只刷新旧写者、新写者及其依赖项。另一个方案是越界时由房主接管，再向客端发送撤权。双客机验证可区分这两种行为，令对象跨出双方区域，观察写者是否还能提交新样本，以及旁观者是否收到隐藏。[Fusion Core 兴趣与持权](https://doc.photonengine.com/fusion-core/v3/manual/interest-area#interaction-with-ownership) · [Core 用例](../../tests/core/game_session_test.cpp)

Fusion Godot 3 按格环降低远处发送率。本项目让原生观察区域声明发送除数，重复订阅同一格时取最快频率，便于用两个区域配置近处和远处。房主按原有格键和对象除数调度。与直接过滤远格相比，限频应保留区外代理的后续状态。比较相同覆盖下的下行、快照间隔、状态年龄和帧时间，可区分节省的分发开销与降频导致的动作停顿。[Fusion Godot 3 降频规则](https://doc.photonengine.com/fusion-godot/v3-shared-authority/manual/interest-area) · [本地配置](../specs/godot-scene-sync.md#空间兴趣与输入预测)

相同除数的对象共享发送步边界时，持续变化的低频对象会在同一步进入构包和接收。本项目按稳定对象 ID 分配周期边界。同一对象的周期仍为有效发送除数，并继续适用基线、可见性和重试门槛。实现取混合后对象号的高位来分配周期，覆盖交错分配的敌人编号。替代方案是对每步设字节预算并按积压顺序补发，会改变高负载的尾延迟。回放可先验证同量记录下每步构包和应用峰值，再与真实房间 TCP 短窗和帧时对照。[发包实现](../../core/state/replication.cpp#L28) · [兴趣回归](../../tests/core/interest_test.cpp)

空间对象的坐标属性也可能是权威端采集的复制字段。Godot 通过根字段布局定位坐标，在已初始化的房主写者采样后复用同一值。代理的本地坐标、限频跳步、生成和其他采集布局继续使用现有位置读取。改用上一网络步缓存会少访问一次 Godot，但会延后跨格可见性。可用带 getter 计数的写者验证每步只采集一次，并在限频下移动到邻格验证可见性按新坐标推进。[采集入口](../../engineplatform/godot/scene_binding.cpp) · [原生测试](../../tests/godot_native/advanced.gd)

### 玩法组件的字段与方法契约

项目沿用字段模板与差量掩码。字段格式发送变动字段的完整集合。协商 word 格式后，编码器可发送长度槽和内容槽中变化的 word，接收端合并后解码受影响的字段。可用只改一个元素的定容列表检查这两种编码的包长。[状态布局与差量](../specs/property-binding.md#状态布局和差量) 对象引用保存房间内的身份，映射由活动会话和本端已绑定的节点共同确定。两个进程的本地节点地址可不同，验收比较解析结果与各自的实际刚体。

命名 RPC 复用稳定方法号和原有可靠性、写权检查。四字节签名用于识别版本或布局不匹配。注册时检查最大编码长度，可使超出单次 RPC 预算的声明在开房阶段被拒。发送方完成连接后通过同号异签名方法发包，接收方处理次数是区分“只按方法号投递”和“校验签名后投递”的指标。见[会话回归](../../tests/core/game_session_test.cpp)。

挂载组件在引擎步中采集或应用字段，写权变化时先取基线。二维和三维刚体复用已有预测表现适配器。普通属性观察者可修正本地误改，刚体允许在快照间运动。该选择依据本项目的写权契约及 [Fusion Preview 555 属性观测](../../research/fusion/findings/property-binding.md)，原版与本项目的二进制表示及调度频率各自独立验证。

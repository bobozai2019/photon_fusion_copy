# 通用游戏同步框架 · 按对象授予客户端状态写权

2026-11-21。计划 [已完成]，实施 [已通过验收]。本轮采用玩家房主授权和每对象单一可委托字段组，Windows x64 同机验收覆盖三进程拼图、三个引擎车场与四人百对象故障场景。

## 交付目标

在普通玩家开的房间里，房主 A 可以把任意已注册对象 X 的一组状态字段交给玩家 B。B 在本地直接产生新状态，A 按该对象的规则检查并转发，玩家 C 能看到结果。同时，计分板可以一直由 A 写，C 也可以获得另一对象 Y 的写权。A 可以把 X 从 B 转交给 C，或收回自己手里。

一个“模型”是一类对象的数据和更新规则。拼图模型在落子时更新格号与朝向，运动模型按固定步更新位置与速度。两个模型使用同一授权接口。“运行时代码”指三个游戏进程实际调用的注册、授权、提交、确认和应用代码。首个演示采用无引擎的三进程拼图，车场用于验证连续运动和引擎呈现。

| 范围 | 本轮建议 |
| --- | --- |
| 本版交付 | 每个对象可委托字段在同一代有一个写入者。房主按玩家、按对象授权。支持同时委托、转交、收回、掉线接管、重连后重新授权。业务归属、RPC 权限和其他字段各按原规则处理。 |
| 本版接入 | Windows x64 普通玩家房主，复用房间、状态复制和 TCP 控制／UDP 状态传输。覆盖拼图、连续运动及 Unity、Godot、Cocos2d-x 现有车场适配。自研验收在本机直接开房即可。 |
| 预留接口 | 模型提供可写字段、业务校验和接管所需数据。沿用当前有限浮点和布尔字段，拼图的格号与朝向只接纳约定范围内的整数值。 |
| 后续独立能力 | 房主权威下的输入预测与重演、原生刚体 Forecast、更多字段类型、房主迁移。部署范围限于玩家房主，Photon Cloud 与独立服务器源码均不构成依赖。 |

## 框架契约

| 操作 | 调用方与关键字段 | 对外承诺 |
| --- | --- | --- |
| 注册模型 | 各端提供模板 ID、模型版本、可写字段 ID 与类型、恢复数据上限、校验规则 | 参与授权的各端先确认模型兼容。既有业务归属 `Object.owner` 继续用于原有 RPC 检查。 |
| 授予、转交、收回 | A 指定对象 ID 与新写入者。可靠消息携带房间、轮次、对象、新代次、基线版本、可写字段值及同一交接点的恢复数据 | 每次换人递增代次。对象与授权基线到齐后新持有者才可提交。重复授权通知不会把本地状态退回旧基线。 |
| 提交状态 | 持权者提供对象 ID、代次、该代的提交序号、可选模拟步、完整可写字段值和恢复数据 | A 以实际连接核对玩家、轮次、代次和字段，并执行模型校验。将接纳的字段合入最新公开对象，再用现有复制路径发布。可合并中间状态，需要逐次结算的动作沿用业务命令或 RPC。 |
| 确认与呈现 | A 确认已接纳提交序号，观察者确认已复制的公开版本。持权者使用本地值，观察者应用公开状态 | 写入者收到较早确认时可继续操作。其他客户端只能看到已接纳的提交。授权失败、掉线或重进后以最后接纳的基线恢复。 |

模型注册、授权查询和提交在会话层完成。字段编解码复用状态层，游戏规则由模型提供。兼容性协商按连接执行，缺少模型或签名不兼容时使用公开复制。房主变更公开版本时合并最新的专属字段，业务归属继续用于原有 RPC 检查。[接口](../../core/session/object_authority.hpp) · [复制类型](../../core/state/replication.hpp) · [房间生命周期](../../core/session/room.hpp) · [RPC 检查](../../core/session/rpc.cpp) · [能力规格](../../docs/specs/object-authority.md)

## 实施顺序与验收

| 步骤与当前状态 | 要做什么、改在哪里 | 通过条件 |
| --- | --- | --- |
| 1 · 契约评审 [已完成] | 核对 `core/session` 的授权契约和 `core/state` 的状态版本，明确默认房主、可写字段、身份映射、恢复数据和旧客户端回退。 | 能逐项说明 B 何时可以写 X、C 何时可见、A 怎么收回，以及写权改变后原有 RPC 谁能调用。 |
| 2 · 通用写权 [已通过] | 接通角色变更、状态提交、复制确认和对象销毁。用两种模板覆盖重复、乱序、已撤销的提交、轮次变化、模型不兼容，以及授予与对象创建的两种顺序。 | 重发同一提交只接纳一次。旧代次、错误玩家和不合规状态均不改公开值。B 持权时，A 同时写的受保护字段能保留。 |
| 3 · 三人拼图 [已通过] | 只依赖 Core 的三个真实进程复用房间与直连传输。房主运行授权和校验，拼图移动在持权端产生。 | B 把 X 从格 2 放到格 5，A 和 C 都读到 5。暂扣发给 B 的下行时，B 仍可在本地落子。C 同时能写 Y。A 把 X 交给 C，C 放到格 9，再放行 B 发往 A 的旧提交，三端最后都是 9，房主专属字段保留。 |
| 4 · 连续模型与引擎 [已通过] | 车场复用相同接口，运动模型保存模拟步与有符号速度。Unity、Godot、Cocos2d-x 提供本地持权视图、远端复制视图和授权快捷键。 | 相同位置分别以正、负速度交接，下一步各自沿正确方向运动。10 Hz 和 40 Hz 发包下均保持 30 Hz 模拟。同引擎分别验证获权、旁观、收回与接管。 |
| 5 · 故障与规模回归 [已通过] | 复用现有四人百对象场景，混合房主写与客户端写，覆盖 UDP 丢包、重复、乱序、掉线重连。 | 重连者先确认基线，再按新代次获权。房主关闭房间后四端正常退出。冻结后四端对象与字段摘要一致，客人共提交 559 次，房主接纳 352 次。 |

先确认第 1 步，再推进第 2 步。协议稳定后，拼图样例与连续运动适配可各自进行。两个模型均通过再进入规模回归。第一份可演示成果以三进程拼图通过为准。

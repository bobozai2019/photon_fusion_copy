# 通用玩法接入计划

目标是在同引擎房间用一个可挂载的组件同步玩法状态，使用有名、有参数类型的方法发送指令。普通玩家开房。运行平台为现有 Windows x64。

| 交付层级 | 范围 |
|---|---|
| MVP | Core 字段与集合、三端类型转换、参数签名与写权校验、挂载后自动采集和应用、Godot／Unity／Cocos 分别双开 |
| 后续 | 任意递归泛型、集合逐元素操作日志、静态语言源码生成 |
| 范围外 | 云服务、异构引擎房间、独立服务器 |

| 任务 | 契约和验收门槛 |
|---|---|
| A 字段 | 追加四维向量、颜色、房内对象引用、字节数组、二维向量数组、整数键值表及有序整数列表。老字段保留原编号；集合声明上限；编码校验类型、容量和完整性。 |
| B 方法 | 通过名称调用；注册时声明稳定方法号、参数模板、方向、可靠性、作用域和写者限制。共用 A 的编解码。参数不匹配、未知方法、错误写者不得触发玩法处理；允许跟踪原有回执。 |
| C 组件 | 会话和对象号只绑定一次。按当前写者自动选择采集或应用，切换写权时先恢复权威基线。引擎管理本地属性和刚体，生命周期内自动更新。 |
| D 联机 | 每款引擎启动两个独立进程，同步非赛车对象，断言新字段实际值、命名 RPC 投递、组件驱动状态；复跑旧 Core 套件。 |

先冻结字段编号和 RPC 签名，再做 C++ 核心。引擎的参数转换和属性绑定可独立推进，双进程验收依赖 A、B、C，三组真实进程顺序执行。计划、[执行状态](执行状态.md)和验收证据分别维护。源码沿用 core/state、core/session 和 engineplatform，各端示例在 examples；复现入口在 tools。

参考实现与依据见 [Fusion Preview 555 的属性与消息观测](../../research/fusion/findings/client-audit.md)、[属性绑定拆解](../../research/fusion/findings/property-binding.md)和[现有会话契约](../../docs/specs/game-session.md)。A 的定长编号及集合格式、B 的方法签名、C 的引擎回调均为本项目选择。变更与可区分的实验见[架构决策](../../docs/decisions/game-session.md)。

## 逐项断言

| 操作 | 本机脚本检查 |
|---|---|
| 房主改变控制台 | 客人读取 8 个实际成员，包括精确整数、四维向量、颜色、指向二维刚体的引用、含零字节的数据、向量数组、含负键及 16777219 的整数表，以及含重复 5 的有序列表。 |
| 移动原生刚体 | 客人从引擎刚体读回位置。二维目标为 Unity 的 4 个世界单位，Godot 和 Cocos2d-x 的 200 个场景单位；三维目标为本端 z=3，容差 0.02 个世界单位。 |
| 交接控制台 | 客人在授权前调用仅写者方法被拒。房主同意后，客人改分至 42，先确认会话中的值，再发送报告。房主同时检查自己的成员值和回调。 |
| 双向命名 RPC | 三个引擎分别验证三参数方法传入单个字符串、或在正确位置传入超出 16 字节的字符串时调用失败。房主验证方法来源、目标对象和三个参数，再调用零参数的房间回复。脚本要求两进程各自通过并以 0 退出。 |
| Core 回归 | 检查新旧字段布局、集合容量、截断输入、重复键、64 位引用、参数数量正确但类型错误、同一方法号的接收端签名不符、销毁后的解析，以及既有复制和房间语义。 |
| 旧车场回归 | 使用 `--authority` 逐引擎复跑权威切换与客人重连。Unity 恢复耗时 1266 ms，Cocos2d-x 1233 ms，Godot 1216 ms。计时包含样例安排的离线间隔。 |

客户端收到对象后，房主可能还在等待其对象可见性或写权模型的确认。控制台在 `Unavailable` 结果后等 250 ms 再请求，收到其他拒绝则报错。只有确认写者后才提交分数。验收脚本的超时仍然生效。

## 复现

以下构建和 `verify_gameplay_components.py`、`verify_godot_scene.py`、`verify_godot_addon.py` 均从 `examples` 仓根目录运行。`package_godot_addon.py` 位于同级 `netcode` 仓。先准备匹配的 Debug Core 和 Release 平台 SDK，见[安装与构建](../../../../examples/README.md)。全套复现使用 Windows x64、Visual Studio 2026 C++ 工具链、Python 3.11+、Godot 4.7.1 及带 Windows Standalone Support 的 Unity 6000.4.0f1。Cocos2d-x 4、Chipmunk 源码和 Bullet x64 安装目录使用下列本机路径，其他机器应替换为实际位置。Godot 安装在非默认路径时可设置 `NETCODE_GODOT_EXE`，构建和联机运行器都会读取它；Unity 构建可通过 `NETCODE_UNITY_EXE` 指向编辑器。构建与联机按顺序执行，避免 Windows Player 占用正在链接的 DLL。[Godot 工具定位](../../../tools/godot_build.py) · [Unity 工具定位](../../../../examples/tools/unity_build.py)

```powershell
python -B tools/build.py --parallel 3
python -B tools/build.py --cocos --godot --unity --parallel 4 --chipmunk-root ../cocos2d-x-4/cmake-build-headless/Chipmunk2D-Chipmunk-7.0.1 --bullet-root ../cocos2d-x-4/cmake-build-headless/3d/bullet-install
python -B tools/verify_gameplay_components.py
```

单测某个平台可加 `--engine godot`、`--engine unity` 或 `--engine cocos`。旧样例复现见[路线图](../../../docs/roadmap.md)。本次新增控制台场景覆盖正常回环下的对象写权交接；弱网和重连结果按各自用例记录。任意嵌套集合、具有增删改语义的集合操作日志和静态源码生成属于后续工作。

## Godot 声明式场景复验

2026-11-22，Windows x64，Godot 4.7.1，Release GDExtension，127.0.0.1。对照 Fusion Godot Shared 的脚本声明方式，在本项目运行玩家房主、取得写权的客人和晚加入的第三人。最终构建在端口 43830、43831、43832 连续三轮通过。每轮三个进程最终都报告 `score=42` 并正常退出，运行器检查了各进程的错误日志。[场景断言](../../../../examples/puzzle/godot/sync/scene_controls.gd) · [复验命令实现](../../../../examples/tools/verify_godot_scene.py)

| 场景 | 核对的结果 |
|---|---|
| 按实例调用 | 两个控制台共用同一脚本。只有左控制台收到写者的报告，只有右控制台执行房主发起的脉冲，本地立即执行一次。 |
| 按玩家调用 | 第三人向当前写者发送非可靠 RPC，写者定向回复第三人。房间接收节点读到发起调用的玩家。 |
| 错误调用 | 未获权发送、未注解方法、向房间接收者指定对象写者、注销后发送、错误参数类型和集合中的 Resource 都被拒绝。 |
| 对象字段与写权 | 客人取得左控制台写权后将分数从 7 改为 42。越权改动灯的可见性被恢复。第三人在观察端改写刚体的自定义字段也被恢复。 |
| 晚加入 | 按场景路径匹配对象，读取节点引用、重复整数列表、颜色数组、超过 32 位的整数、脚本类数组，以及三维刚体和二维角色状态。 |
| 集合 RPC | 指定玩家收到嵌套字典（含字符串和 64 位整数）及类型化颜色数组，其他玩家未执行定向回调。 |

复现执行 `python -B tools/verify_godot_scene.py`。原有控制台通过 `python -B tools/verify_gameplay_components.py` 回归，Godot、Unity、Cocos2d-x 各自的双端均报告八字段、引用、二维和三维刚体及双向方法通过。Godot 编辑器通过无界面导入，本轮未人工点选属性选择器。验收使用自研协议和本机玩家进程。[Godot 接入与容量边界](../../../docs/specs/godot-scene-sync.md)

## Godot 插件安装和属性选择

2026-11-22，Windows x64、Godot 4.7.1。将交付 ZIP 解压到独立测试工程，通过 Godot 的 EditorPlugin 和 Inspector 打开字段面板。测试通过控件选择根节点脚本的 `:score`、子节点 `Light:visible` 和复合属性 `:stats:points`，随后切换客户端写权、撤销、重做并保存，重新实例化后得到相同的写权字段。[编辑器验证](../../../../examples/tests/godot/addon_picker_probe.gd)

- `python -B tools/package_godot_addon.py` 生成包含 `addons/netcode` 的 Windows x64 插件 ZIP。`python -B tools/verify_godot_addon.py` 在独立工程安装归档并验证属性选择器。
- 普通图形编辑器在空缓存工程首次扫描后正常退出。本机在无缓存、无扩展索引时直接运行 `--headless --editor --import`，会在退出时返回 Windows 异常码 0xC0000005。自动化使用仓库的 `import_project` 先登记扩展路径，已验证能正常导入和退出。
- 迁移到插件之后，Godot 三人写权与 RPC 场景、旧双端组件场景、Windows 导出 Player 的二维／三维属性绑定测试均通过。

# T3 · 双端生成、首值和暂存回收

Godot 4.6.1 Windows x64，B 在两个 Spawner 中发起三次生成，涵盖默认模板和显式模板。三个模板共用同一字段布局与外部配置。A 按目录中的场景身份分别创建 Orb、Other、Third，两进程的断言通过。

| 端 | 第一个模板的实际事件 |
| --- | --- |
| B | 预回调读 `-1`，setter 写 `731`，入树，`_ready`，Replicator spawned，Spawner spawned，当次同步返回。入树以后都读 `731`，回调和返回时都有本地权威。随后三实例都达到可写状态。 |
| A | 入树与 `_ready` 都读 `-1`，首个 setter 写 `731`，随后两个生成信号都读到 `731`。记录中 A 全程无写权。其它两个模板的首值为 `732` 和 `733`。 |

关闭房主的客端生成选项后，B 仍先获得暂存节点。在收到一次 `spawn_failed` 后，弱引用断言该实例已经释放。在每方向注入 35 ms 延迟的 TCP 中转中，B 取消尚未确认的请求，再提交一个请求并立即离房。A 与 B 均断言暂存和世界实例已回收。正常双端首值和信号顺序与 555 Cloud 对照一致。[T0](T0.md)

完整测试使用 `python -B tools/verify_godot_native.py --addon <SDK ZIP>`。拒绝和延迟回收分别可用 `--case reject` 与 `--case cancel` 单跑。

## 两轮复审回归

第一轮在 Godot 4.6.1 双端验证生成后立即写入。房主写入 73，观察端收到 73。客端在暂存节点同步返回后将 731 改为 741，房主先收到 731，随后收到 741。远端 `_ready()` 删除 Sync 的对象被隔离，其他对象继续同步。

第二轮将房主的 Node 引用赋值移到预生成回调，客端解析出同一房间内已绑定的目标。新增三条重入断言，分别覆盖房主在 `_ready()` 里调用 `despawn()`、远端首包 setter 移除 Sync、远端 `Sync.spawned` 回调销毁根节点。双端退出码为 0，生命周期夹具检查了对象回收与后续信号。目标晚挂载和重新进入兴趣后的引用恢复仍缺专门夹具。

`python -B tools/verify_godot_native.py --addon <SDK ZIP> --case lifecycle`

## v5 入房回调生成

在 TCP 中转每方向增加 35 ms 延迟。B 在 `room_joined` 中直接同步生成三种模板，仿真时钟尚未就绪，三个本地节点均可访问。房主先接收 731、732、733，再接收 B 在 `spawn()` 返回后写入的 741。加入了就绪前取消和从 `_ready()` 重入取消的断言。后者使调用返回空值并停止两个生成信号，房主未出现被取消对象的字段或信号。复审核对了握手就绪当帧仍按队列顺序发送，以及房主预分配输入权的旧路径。

## 对齐返回后赋值

同一个 35 ms 双向中转夹具保留入房回调和取消断言。B 对 Orb 在预回调写 731，返回后立即写 741。Other 直接 `spawn(scene)`，返回后写 742。Third 只通过预回调写 733。生成端的 `_ready` 和两个信号读到 731、-1、733。A 的 `_ready` 读到 -1，首个 setter、Replicator 与 Spawner 的生成信号分别读到 741、742、733。B 在正式写权就绪后另写 751，A 随后收到 751。

房主发起的生命周期夹具在预回调写 1，返回后写 73。客端的首个 `Spawner.spawned` 直接读到 73，并解析已绑定的引用。分开的回归覆盖了发送前取消、发送后确认前取消与离房、拒绝、首包进树时解绑。协议版本保持 v5。[Fusion 555 首值对照](T0.md#同一调用栈中的返回后赋值)

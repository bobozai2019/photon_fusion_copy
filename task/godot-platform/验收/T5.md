- yard 的双端赛车通过双向运动和离房实例回收。puzzle 的三进程场景用例三端终值都是 42，独立导出用例两端分数 42、八字段和双向 RPC 通过。shiftline 使用隔离副本验证旧场景，覆盖房间、地图、玩法、结算、菜单和远端动作。
- sync-lab 在实际工作目录安装 ZIP 后，启动测试检查了退出 Netcode、切换到 Fusion、恢复 TCP 地址和同端口重新开房。Fusion Local 启动测试确认 5055 连接报 1039。独立 SDK 命令以更新后的示例锁复跑成功。

## 复现

在 netcode 根目录运行 `python -B tools/package_godot_addon.py`，验证命令中的 ZIP 使用该绝对路径。

```powershell
python -B tools/verify_godot_native.py --addon <SDK ZIP>
python -B tools/verify_godot_native.py --addon <SDK ZIP> --export --godot <Godot 4.7.1 console exe>
```

在 examples 根目录运行下列命令。

```powershell
python -B tools/verify_sync_lab.py 128 --sdk <SDK ZIP>
python -B tools/verify_sync_lab.py 512 --sdk <SDK ZIP> --seconds 42
python -B tools/verify_sync_lab.py 128 --sdk <SDK ZIP> --backend Fusion --cloud --seconds 47
python -B tools/verify_godot_racing.py --addon <SDK ZIP>
python -B tools/verify_godot_scene.py --addon <SDK ZIP>
python -B tools/verify_godot_fps.py --suite all --addon <SDK ZIP>
python -B tools/verify_sdk_install.py godot
```

旧 TCP 复验可向负载脚本传 `--baseline-backend`，指向原始 `backend_netcode.gd`。本次使用保留的 `examples/out/tmp/sync-lab-fusion-stall-baseline/project/backend_netcode.gd` 与 `netcode/out/tmp/property-backpressure/netcode-godot-win-x64.zip`。基线追踪从原有场景的可见集推导 AOI 状态。

## 512 对象的双窗口帧率

Windows x64 同机运行 Godot 4.6.1，GeForce GTX 1050，Netcode 本机 TCP，两个 930 × 690 窗口，项目上限 60 FPS。使用 `e1b235b897d43875/c8c2126b9779249e` 原生 DLL 和同一套八字段负载。每个小球 10 Hz，房主实际约每秒写入 5,100 次。下表取预热后、全量可见时约一秒采样窗的中位数。

| 实现 | 房主 / 客机 FPS | 房主 / 客机每帧绘制调用 | 房主 / 客机 Arena 单次重画 |
| --- | --- | --- | --- |
| 逐球绘制、通用回写 | 20.3 / 8.2 | 682 / 679 | 10.9 / 11.0 ms |
| 批量绘制、通用回写 | 59.9 / 18.4 | 46 / 42 | 2.04 / 2.01 ms |
| 批量绘制、根字段直接回写 | 60.1 / 60.0 | 46 / 42 | 2.05 / 1.95 ms |

独立分段计时覆盖采集、`sync_replica` 调用和场景回写。批量绘制时，旧客机回写在每个物理步约 5.15 ms，直接回写后为 0.69 ms。优化后客机同一口径下字段采集约 2.75 ms/步，转换和 Core 同步调用约 3.24 ms/步。旧绘制的无窗口对照为 60.0 / 54.2 FPS。窗口关闭垂直同步并将上限临时调至 120 FPS 后，优化版达到 102.8 / 102.7 FPS。

Arena 用一个 2D MultiMesh 提交小球及光晕，仍按原索引顺序绘制。原生适配器复用采样时缓存的根属性名和类型，按字段顺序应用无需插值的普通属性和 64 位整数。发生一次 setter 调用后，遇到采样时已经匹配的后续字段仍会复读当前值，以处理前一个 setter 改写后续字段的情况。原生 Shared 双端回归覆盖同次回写内恢复后续字段，也通过了生成顺序、写权交接、兴趣分发及预测用例。

42 秒双窗口 DemoCheck 的 512 档 FPS 中位数为 60.00 / 59.99，P95 帧间隔的采样窗中位数为 18.99 / 21.02 ms。房主 1 个、客机 511 个远端对象的八字段检查通过。客机可见集合为 512 → 268 → 268 → 512，满负载全量视野每窗推进远端对象数的中位数为 511。128 档双窗口也通过，客机可见集合为 128 → 76 → 76 → 128。

### 主客机从节点到 TCP 的分段计时

在相同 512 对象、八字段、约 5,100 次写入/秒的 Windows 双窗口负载下，使用 `7c86097d5ebf426f/07323cf307cecc3f` 编译选项和库制作临时计时 DLL。在 Godot 场景适配器、Core 快照和传输入口累计墙钟耗时。取预热后的全量采样窗中位数，以约 512 次 `sync_replica` 调用折算一个物理步。表中网络阶段也按该口径归一化，网络推进本身在空闲帧运行。两次优化版结果的区间如下。

| 阶段，ms/物理步 | 房主 A | 客机 B |
| --- | ---: | ---: |
| 业务脚本产生小球新值 | 1.28–1.48 | — |
| 从节点读取八字段 | 2.72–2.84 | 2.63–2.67 |
| `sync_replica`，含语言边界、类型转换和 Core 状态处理 | 2.87–3.02 | 3.14–3.19 |
| 快照组包与压缩 | 0.38–0.39 | — |
| TCP 轮询及提交 | 0.09–0.10 | 0.12 |
| 快照解压、解码并写入 Core 副本 | — | 0.18–0.20 |
| Core 状态回写 Godot 节点 | 约 0.004 | 0.67–0.69 |

两端每个物理步都读取约 512 个节点。客机也采样代理的当前属性，Core 以此判断是否需要纠正本地偏差。`sync_replica` 内部，Godot 值转为 Core 值占约 1.5 ms/步，Core 的比较与提交或准备应用约 0.8 ms/步。客机另用约 0.27 ms/步把待应用值转回 Godot 类型。这三项已经包含在表中的 `sync_replica` 一行。房主按每个接收方的确认版本构包，并用字段掩码编码更新的数据。TCP 计时覆盖本机调用，链路传输和调度等待体现在状态年龄。

保留同一个计时 DLL、批量绘制和负载，仅换回通用回写脚本时，房主仍为 60.0 FPS，客机为 13.6 FPS。客机回写约 5.05 ms/物理步，每次进入对象回写约 61 µs。直接回写时该调用约 11–12 µs，客机恢复为 60.0 FPS。通用回写会做目标路径解析、字段类型分派，以及前一 setter 可能改动后续字段时的复读。主机的采集和类型转换同样占用预算，但这部分双端都做。快照组包、压缩和 TCP 提交在本机双端场景只占主机一小部分时间。

### Shared 代理按变化回写

Fusion Core 在发送侧通过 `Words`、`Shadow` 和逐 word 变更时间跟踪差量。接收侧由 Core 更新本地 `Words`。Preview 555 Linux Godot 分支消费对象更新标记，并用上次解码值筛出普通字段的 setter 调用。Preview 555 Web 普通字段探针验证了稳定代理的 getter、setter 都为零，以及权威端只改字段 B 时，代理对字段 A 的改动会继续保留。Fusion 的插值、强制重置、类型化 Array 和权威切换有各自的行为边界。[Fusion 对象同步模式](https://doc.photonengine.com/fusion-core/v3/integration/object-sync-patterns) · [555 静态接收路径](../../../research/fusion/findings/property-binding.md#接收更新标记与普通字段回写) · [原版代理实验](../../../research/fusion/findings/property-profile.md#行为对照与实现边界)

Netcode 的 `apply_proxy_changes_only` 在实例绑定时读取。稳定代理每个物理步检查 Core 对象版本，版本推进后比较上次呈现值并只将发生变化的字段送进 Godot。代理首次挂载、AOI 重绑和写权代次切换仍按模板顺序应用完整基线。当前范围是原生 Shared 的根节点普通字段，默认逐步纠偏的语义继续可用。[配置及边界](../../../docs/specs/godot-scene-sync.md)

#### 权威节点直接由 C++ 采集和提交

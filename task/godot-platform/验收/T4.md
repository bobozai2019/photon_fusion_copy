# T4 · 写权、RPC 和用户兴趣键

Godot 4.6.1 Windows x64，A 和 B 使用两个 TCP 进程。场景有一个全局对象、键 1 自动释放对象、键 2 保留对象。

- B 请求 Transaction 写权。A 首次拒绝，B 收到 `authority_response(false)` 并继续只读。A 第二次批准，B 等到正式基线后将字段写为 500，A 读取该值。
- A 向当前 Owner 调用加 49 的对象 RPC。B 执行方法，A 收到成功回执并读取 549。B 调用一个不存在的玩家，收到交付失败回调。插件目标返回不支持。A 收回写权后写入 937，B 读取 937 并失去写权。
- B 单独删除键 1，该实例被释放，键 2 和全局对象保留。删除键 2 后，该实例保留并解除绑定。A 趁两组都在视野外写入 911 和 912。B 重订阅后，键 1 建立新实例，键 2 以原实例重绑，均得到最新值。
- A 在两组再次离开视野时全局销毁它们。B 的保留实例最终释放。B 再订阅时两个对象都未复活。

`python -B tools/verify_godot_native.py --addon <SDK ZIP> --case shared` 验证两端退出 0。Core 的旧代写入保护同时由 `object_authority` 回归套件覆盖。

## 第二轮复审回归

- A 批准 B 之前先向当时的 Owner 发送 RPC。调用在写者交接后报告失败，夹具未观察到方法执行。这个用例同时改变了玩家和写权代次。
- A 收回写权的同一帧提交 Owner RPC。调用等到新基线，字段由 549 变为 552 一次。A 同帧发起被 `@rpc("authority", "call_remote")` 标注的广播，B 执行一次，A 无本地执行。B 在还未取得写权时调用该方法会失败。
- B 未订阅键 1 时生成键 1 模板，当次返回 `null`。A 的本地加键和删键均返回 `false`，仍可管理全部对象。
- Windows Release 导出的 B 在同一帧重订阅键 1 并生成键 1 模板，成功收到正式写权基线。

## 原生协议 v3 的 RPC

独立审核后，房间 RPC 按协商名单路由。对象 RPC 继续检查写权与可见性。双端套件验证了 `Netcode.rpc()`、`Netcode.rpc_to_player()`、回调内上下文、视野内的 Node 参数及隐藏后收到的 `null`。两个同名广播接收者各自收到未被另一个接收者修改的容器。调用 `Callable.unbind(1)` 时尾参不进入消息。复制根的 `rpc_methods` 中声明了与 Sync 原生方法同名的脚本方法，直接向 Sync 调用该原生方法会被拒绝。

Core 的内存传输用例在第三位玩家的首份名单快照之前送达另一客端发来的房间 RPC。用例核对两条包的顺序、收件方缓存的真实发件人与目标，以及协商后的成功回执。复跑使用 `ctest --test-dir out/build/win-x64/sdk/core/Release -C Release -R game_session --output-on-failure`。

## 原生协议 v4 的 RPC 和写权

房主和客端各发一条 `call_local` 广播，在调用返回前观察到本机回调。远端也执行，回执后两端均无回送重复。房主作为已就绪 Owner 可同步处理，处理函数修改嵌套数组时调用者的数组未变。客端作为 Owner 会等待房主确认代次，再执行一次。

Core 的内存传输回归让房主对两位客端发送 256 次广播，填满 512 个未结投递。第 257 次直接报告未受理，房主投递队列也没有产生发送端回送。

双端 Transaction 覆盖多个同步回调对拒绝与批准的聚合、源节点参数和 `unbind(1)`、deferred 显式应答及 one-shot 断开。客端可拒绝房主普通请求，房主仍可从独立入口执行管理员收权。反向批准用例让房主重新取得写入基线，再由客端请求。房主回调中解绑 Sync 后，旧节点尝试提交应答会失败，该对象只回收一次。

## v5 RPC 回调

同一双端夹具核对 `Netcode.get_rpc_sender()` 与原有上下文。当客端发来的 RPC 在房主嵌套同步调用本地 RPC 时，外层依次读到 2、2，内层读到 1，退出回调读到 0。两个广播接收者均如此。

不可用玩家触发异步失败，不支持的插件目标触发即时失败。两条路径都覆盖零参 `on_fail()`。一参及可变参接到错误字符串，TTL 沿用原规则。[Fusion GDScript 调用方式](https://doc.photonengine.com/fusion-godot/v3-shared-authority/manual/csharp-bindings#rpc-context-and-results)

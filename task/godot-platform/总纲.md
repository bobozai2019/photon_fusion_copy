# Godot 4 平台接入执行计划

本计划记录首次接入 Windows x64 Godot 时的范围。当前 Godot 原生节点、生成与编辑器工具见[场景同步手册](../../docs/specs/godot-scene-sync.md)。首版 Godot 车场复用了 C++ 核心、直连传输和车场逻辑。以 Cocos2d-x 的 M0–M6 为能力基准，第一阶段以 Godot ↔ Godot 验收。[Cocos2d-x 原验收](../cross-engine-sync/执行状态.md) · [当前阶段范围](../../docs/roadmap.md#第一阶段验收)

| 分类 | 内容 |
| --- | --- |
| MVP | GDExtension、Godot 双窗口车场、2D/3D 绑定、房间和 RPC、断线续玩、四人百对象、Windows 独立导出和包内复跑 |
| placeholder | 其他传输后端通过现有接口接入 |
| vNext | Windows 双设备实测及其他操作系统上的传输 |
| out_of_scope | Photon 协议互通、编辑器插件和改变现有模拟规则 |

## 需求映射、依赖和门槛

| 任务 | 基准 | 前置 | 验收 |
| --- | --- | --- | --- |
| G0 独立构建 | M0 | 仓库侦察 | 核心独立构建，Godot 空窗和 GDExtension 启动 |
| G1 房间与复制 | M1、M2 | G0 | 同一套内存与真实 TCP/UDP 测试；Godot 两端观察输入、权威写入和快照应用 |
| G2 节点和玩法 | M3–M5 | G1 | 2D/3D 轴、独立字段、子节点重绑定、插值、路障寿命、RPC 权限与可靠顺序、原身份和原车恢复 |
| G3 规模与收敛 | M6 | G2 | 两个 Godot 窗口加两个轻量客人，通过基线及丢包、乱序、重复测试 |
| G4 交付 | 分发要求 | G3 | Godot 独立导出、包内联机、单独包槽；审核上传清单并推送 GitHub |

适配契约稳定后，场景与构建工作可独立开展。负载观测期间只运行待测场景。Windows 导出依赖同版模板，开发项目依赖本机 Godot，核心测试直接运行 C++ 测试程序。

原生桥见[适配器契约](契约/适配器.md)，运行态见[执行状态](执行状态.md)，实测记录进入 `验收/`。接口在 `engineplatform/godot/`，可玩项目在 [示例仓的 Godot 车场](../../../examples/yard/godot/README.md)。先独立构建并验证空窗，再用共用脚本推进双端和负载场景。

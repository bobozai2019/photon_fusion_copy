# Godot 接入契约

`NetcodeYard` 由 GDExtension 注册。场景读取共用的 `replicators.cfg`，交给 C++ 样例解析。房主和客人的连接、序号、局次、RPC、确认及对象身份沿用原协议。[运行时契约](../../../docs/decisions/first-edition-runtime.md)

| API | 请求 | 返回及失败 |
| --- | --- | --- |
| `configure` | Godot 用户参数、UTF-8 配置 | 成功为空字符串，失败为可显示的错误 |
| `bindings` | 初始化完成 | 模板 ID 到有序字段清单，含 `id/path/property/transform` |
| `advance` | 每个 Godot 进程帧调用 | 房间阶段、席位、局次、玩家和车辆 ID、准备状态、拒绝与结束原因。对象含 `id/schema/owner/revision/values`。错误通过 `error`，退出码通过 `status` |
| `drive` | `throttle`、`steer`，范围 −1 至 1 | 交给共用逻辑处理，非法值无法进入驾驶状态 |
| `act` | `start/end_round/end_room/disconnect/rejoin/gate/place/remove/horn` | 操作交给当前会话，业务结果通过房间状态、复制字段或业务通知体现 |

Godot 层按共享字段顺序及本地 NodePath 写根和子节点。二维显示以左上为原点且 Y 向下，网络坐标从左下计算。三维在正交 SubViewport 中直接使用世界坐标。变换插值为 100 ms，业务字段直接应用，删除由当前对象集合触发，失效节点按路径重解析。

独立实现第二套房间和状态协议也能产生相似画面。验证用同一个 `yard_match` 链接目标，并让两引擎互换房主后比较最终状态以区分。结论适用于现有 C++ 核心与 Windows 直连后端。[GDExtension 兼容性](https://docs.godotengine.org/en/stable/tutorials/scripting/cpp/about_godot_cpp.html)

# 通用客户端与 Fusion 的 13 项对照

此表记录深化前的代码基线。最新运行结果与逐项剩余差异见[客户端框架深化验收](深化状态.md)。

本表对应[执行计划](执行计划.md)。对照依据为 Fusion 3 Core 官方公开契约、仓库保留的 [Godot Preview 555 原版运行观测](../../research/fusion/findings/client-audit.md)及深化前的自研源码。当前在线手册和 555 分别注明。自研侧本轮复跑 Windows Debug 已构建产物的 10 组 CTest，10 组通过；三引擎和弱网指标沿用[上一轮本机记录](验收/本机联机.json)。最后一列给出可区分差异的实验，列入该列不表示已经进行双实现对跑。

| 计划项 | Fusion 侧依据 | 自研实况与玩法影响 | 可区分差异的实验 |
|---|---|---|---|
| 1. 引擎和脚本入口 | 555 的 Godot 插件可以从场景导出复制布局，预测重置和对象就绪可交给玩法脚本处理。 [官方资料](https://doc.photonengine.com/fusion-core/v3/integration/engine-binding) | 三端能用同一份 cfg 做合作机关。Godot、Unity 的通用门面暴露生成、申请写权、字段和地图事件；自定义预测单步、通用 RPC 和兴趣订阅仍从 C++ Core 接入。 [源码或实测](../../engineplatform/godot/game.hpp) · [补充依据](../../engineplatform/unity/managed/NetcodeGame.cs) | 只给 GDScript 或 C#，要求新增一种预测技能、订阅兴趣键和调用对象 RPC，记录哪一步需要扩展绑定。 |
| 2. 对象写权 | Fusion 在创建实例时选择归属模式。555 的事务样本中，持有人拒绝后权限保持，批准后两端看到新 owner。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/ownership) | 已经有抢占、答复、冷却和交接。自研策略按 schema 登记；相同模板想同时生成房主专属和可抢占的物体，需要拆模板或扩展接口。客人走生成工厂时创建者记在对象上；未授予写权时 writer 默认是房主。 [源码或实测](../../core/session/ownership_requests.cpp) · [补充依据](../../core/session/object_authority.cpp) | 用同一模板生成上述两个实例，另检查客人申请生成后、第一次 claim 前谁能写入。 |
| 3. 对象身份与寿命 | Fusion 动态 ID 含创建玩家、地图和计数，创建方可直接获得 ID。地图全局实例由地图与 hash 标识。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/object-creation) | 自研房主统一分配实例号。客人先拿请求序号，再等 SpawnResult；支持地图稳定键、挂接和级联销毁。该基线的 GameGlobal 仅支持地图 0 下每模板一份。后续实现增加了带键实例，同模板可按 `(scene, key)` 区分，现行约束见[会话规格](../../docs/specs/game-session.md)。 [源码或实测](../../core/session/world.cpp) · [补充依据](../../core/session/world.hpp) | 两个客人同帧生成并立即引用，检查第一个可用 ID；再尝试同模板创建两个不同键的全局实例。 |
| 4. 多地图和场景就绪 | Fusion 支持整体换图、叠加和移除。555 原版实际测到增量加载后引擎挂载点出现节点，卸载后移除。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/scene-management) | 自研可同步多图、屏蔽未就绪对象和拒绝旧代次。接口分别 load/unload，载荷为资源名；机关脚本识别资源名便回复 loaded。该测试只证明网络门槛，未证明三个引擎都实际完成异步资源装卸。 [源码或实测](../../core/session/world.cpp) · [补充依据](../../../examples/puzzle/godot/plates/plates.gd) | 在非空场景异步加载中途卸图再重载，同时观测真实节点数、旧就绪事件和对象首次可操作时刻。 |
| 5. 预测和纠偏 | Fusion Host 的权威状态带回已消费输入，预测者从新基线重放。555 实测同一批 60 个独立输入在房主只执行 60 次，预测端发生多轮重演。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/ownership) | 核心机制已对应。自研两个模型都通过了 180 ms 暂扣下行与逆序恢复。单步注册在 C++，待确认输入容量 128；通用 C# / GDScript 门面缺少等价的玩法预测重置和重演回调。 [源码或实测](../../core/session/model_prediction.cpp) · [补充依据](../../core/state/prediction.hpp) | 把同一套带序号输入送入双端，核对确认序号、回放后状态以及一次性音效是否重复。两实现的回调次数应分别记录。 |
| 6. 网络时间 | Fusion Core 以服务端时间为基准，通过状态包取样。手册描述了误差阈值、速率调整与大偏移时跳时。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/time) | 自研从房主回显估计 RTT 和偏移，平滑修正速率上限为 ±10%。三种房主的 3.2 秒倒计时触发跨度分别为 28、22、33 ms。时钟源、滤波与停顿恢复的规则不同。 [源码或实测](../../core/session/network_clock.cpp) · [补充依据](../../core/session/network_clock.hpp) | 输入相同的非对称延迟和长暂停，画出恢复后两秒的偏差、速率和倒计时触发次序。 |
| 7. 兴趣与发送频率 | Fusion 在根对象上设兴趣键，子对象跟随根；玩家订阅区域键、用户键。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/interest-area) | 自研支持区域、用户、多键和独立频率。挂接对象同时受父可见性和自身分组限制。因此可能父可见、子隐藏。玩法还需要通过 Core 配置这些分组。 [源码或实测](../../core/state/replication.cpp) · [补充依据](../../core/session/world.cpp) | 根对所有人可见，挂件设为仅红队。比较蓝队收到的对象集合，区分父级继承和父子条件相交。 |
| 8. RPC 路由和结果 | Fusion 公开目标玩家、目标对象、事件标识、字节载荷和投递错误。玩法可以分别查询当前 owner、选择目标。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/rpcs) | 自研支持可靠投递、按可见性过滤与逐目标结果。方法预注册固定参数长度；部分方向用 Object.owner 做访问检查或选择收件人。状态写权另查 grant.writer。房主生成的机关交给 B，B 能写字段，仍可能发不出该机关的 Server 方向 RPC。Received 仅证明收包。 [源码或实测](../../core/session/game_session.cpp) · [补充依据](../../core/session/rpc.cpp) | 交接前后分别由旧、新写者调用同一对象方法，记录返回值、接收者和远端业务执行次数。 |
| 9. 布局和编码 | Fusion 以定长 Words 与 Shadow 比较状态，字符串可用带代次的句柄，消息流另有变长编码。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/serialization) | 自研是九种带类型字段、对象修订号、每接收者确认的快照字典和可选量化。453 B 降到 56 B 是自研同一负载的新旧编码对照。不能据此比较 Fusion 带宽。两者的数据布局和线协议不同。 [源码或实测](../../core/state/value.hpp) · [补充依据](../../core/state/snapshot_codec.cpp) | 在两套实现重放相同字段序列、确认节奏和丢包轨迹，分别报告总字节、CPU 与内存。 |
| 10. 原生刚体 Forecast | 555 有 2D/3D 原生分支，Racing 实例读取到 Blend、最大外推 0.25 秒；已观察代理碰撞、传送、休眠。 [官方资料](https://doc.photonengine.com/fusion-godot/v3-shared-authority/manual/physics-replication) | 三引擎原生二维样例已验证相同类别的可见行为。自研 Godot 适配器将外推限制为 0.1 秒，按位置误差改速度。三维刚体和 Force/Blend 等模式未获得对应覆盖。 [源码或实测](../../engineplatform/godot/forecast_body.gd) · [补充依据](../../research/fusion/findings/native-runtime.md) | 使用等价初态与碰撞体，按同一时间基准记录每步位姿、速度和接触；终点一致只能验证静止收敛。 |
| 11. 准入、断线和重入 | Photon 区分普通加入和显式重入。555 Godot 暴露玩家和空房 TTL；原版实测相同 User ID 普通重进取得了新玩家号。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/connection) | 自研已有容量、迟入、旁观只读和凭票恢复。局中掉线保留席位，RoomOptions 没有玩家和空房 TTL 配置；对象写权在连接断开时走处置。前述票据和成员寿命需要分别看。 [源码或实测](../../core/session/room.cpp) · [补充依据](../../core/session/room.hpp) | 设置短 TTL，在到期前后分别普通加入和凭票重入，对比玩家号、席位与 PlayerAttached 对象。 |
| 12. 房主接替 | Fusion Shared 的 Photon 房间继续存在，服务切换 Master。555 实测两人房里 A 正常离开，B 独自留下并接手全局状态。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/ownership) | 自研需要迁移实际监听端点和世界。至少三名投票玩家、预设可监听的热备、过半数，支持一次接替。三进程强杀后 1782 ms 确认下一次写入；恢复点以最新完整检查点为准。两人合作游戏无法依靠此路径在房主退出后单人续局。 [源码或实测](../../core/session/migration.cpp) · [补充依据](../../core/session/checkpoint.cpp) | 分别测两人正常退、三人强退、连续两次退，独立记录可恢复步、下一次写入与尚未完成的事件。 |
| 13. 发现和匹配 | Fusion 的房间、区域和身份由 Photon Realtime 提供，可使用大厅与随机匹配等服务。 [官方资料](https://doc.photonengine.com/fusion-core/v3/manual/connection) | 本地目录已验两房筛选、最后一席竞争、满员持票重入与迁移端口更新。区域在此是公告过滤字段；这条链路覆盖本地找房，不提供 Photon 跨网房间目录、区域服务与账号认证。Steam 依约跳过。 [源码或实测](../../core/session/discovery.hpp) · [补充依据](../../core/transport/lan_directory.cpp) | 本地用两个广播房间核对筛选即可验本版；跨网目录与账号认证属于另一种部署条件。 |

# 房主接替、刚体组回放与编码对照

2026-11-21，Windows x64。本轮使用普通玩家开房和回环连接。三维场景由箱体、地板和固定关节组成，和赛车样例独立。Steam、公网和独立服务器照约定跳过。原始指标汇总见[本机验收数据](验收/余项本机.json)。

本报告的九组回放误差用于物理样例诊断。混合引擎实验作为历史技术证据，产品按各引擎内部联机验收，标准见[当前项目目标](../../docs/roadmap.md#当前项目目标)。

## 1. 同一脚本会话连续更换两次房主

| 房主顺序 | 强退原房主前，玩家 2 最后报告的完整检查点 | 三任之间跟踪的对象 |
|---|---:|---|
| Unity → Godot → Unity | 第 7 步 | 77 → 88 → 89 → 90 |
| Godot → Unity → Godot | 第 8 步 | 77 → 88 → 89 → 90 |

每轮有三个独立玩家进程。玩家 2 在看到对象后等待热备检查点继续前进，玩家 3 同时确认已读到 77。运行器强制结束首任房主。第二任通过脚本接替事件恢复同一对象，保留字符串及第三个整数字段，并把 77 写成 88。玩家 3 读到 88 后向新房主发送已注册的可靠 RPC。第二任写入 89 并主动交接，玩家 3 恢复 89 再写成 90。两轮主动交接的第二任房主均在收到确认后结束。另用 C++ 入口复验了原玩家身份、写权代次、两个预测模型的已消费输入和 LAN 房间端点更新。[三进程验收程序](../../../examples/tools/verify_script_handoff.py) · [脚本接入说明](../../docs/specs/game-session.md)

修复了一项只看幸存者时容易漏掉的问题。控制通道发送成功表示消息已排队。原实现可能在交接确认实际写入套接字前销毁旧连接。现在接任者验证并恢复最终检查点后发送确认，并给原连接机会排空待发数据。原生和引擎脚本用例都检查正常交接时旧主确实结束。房主突然退出时，恢复点仍是热备已经收全的检查点。两人突然分区时继续沿用防止双主的规则。[迁移实现](../../core/session/migration.cpp)

## 2. 三维关节与堆叠的九组联机回放

房主保存四个动态体的同一步状态。两个箱体堆叠，另两个由固定关节连接。第 41 步对关节施加偏心冲量，确保第 45 步检查点包含运动中的速度。第 48 步再次施加冲量，并给客人的一份预测额外施力以制造分歧。客人通过网络接收第 45 步和第 70 步两份完整组状态，在独立物理空间恢复第 45 步并回放 25 步。两份状态均通过通用复制对象传送，客人用 RPC 向房主确认验收。[字段布局](../../../examples/puzzle/island.cfg) · [九组合运行器](../../../examples/tools/verify_physics_island.py)

以下为第 70 步、四个刚体中最大的世界坐标位置偏差，单位为毫米。每行是独立一局。“最终”包含按需应用该步的权威状态。最后一列的零表示这一次同步后测得的值。

| 房主 → 客人 | 错误输入后 | 回放后 | 应用第 70 步权威状态 | 最终 |
|---|---:|---:|---|---:|
| Godot → Godot | 427.61 | 2.87 | 否 | 2.87 |
| Godot → Unity | 206.29 | 44.72 | 否 | 44.72 |
| Godot → Cocos | 936.77 | 60.26 | 是 | 0 |
| Unity → Godot | 430.67 | 17.60 | 否 | 17.60 |
| Unity → Unity | 209.17 | 2.66 | 否 | 2.66 |
| Unity → Cocos | 939.78 | 63.85 | 是 | 0 |
| Cocos → Godot | 426.12 | 17.24 | 否 | 17.24 |
| Cocos → Unity | 204.80 | 24.61 | 否 | 24.61 |
| Cocos → Cocos | 935.25 | 7.38 | 否 | 7.38 |

采用同一门槛严格验收时，七个组合的回放误差低于 60 mm，两个组合越界。开启样例的按需校正后，这两个组合恢复最新的同一步权威组状态，验收要求此时误差小于 1 mm。所有组合另验关节间距偏差小于 25 mm、两次独立冷启动相对误差小于 1 mm，以及拒绝缺少成员的检查点。原生求解器的接触缓存仍属引擎内部状态。本次量化的是一个指定步的最大位置偏差，尚缺整段旋转与速度误差、长关节链、二维多体及原版 Fusion 对应场景的逐步对照。样例的 60 mm 容差由本项目选定。[Unity 组适配器](../../engineplatform/unity/managed/PhysicsIsland3D.cs) · [Godot 组适配器](../../engineplatform/godot/physics_island_3d.gd) · [Cocos 组适配器](../../engineplatform/cocos2dx/physics_island_3d.hpp)

## 3. 原版与自研使用同一输入

双方均更新 600 步。每步写入递增整数，保留 80 个 Q 的字符串，并修改 40 项整数数组的一个位置。最终数据摘要均为 1124070639。原版探针在核对插件指纹后启动 Preview 684 单机房，通过公开 API 创建本地权威对象。在 600 个物理帧中，其标量 getter 被同步系统读取 0 次，shadow 标志为 false，运行时布局为 134 words。现场有 0 名远端玩家，实际发给对端的编码消息及编码 CPU 均未取得。[原版探针](../../research/fusion/probes/editor_fixture.gd) · [原版复现步骤](../../research/fusion/probes/README.md)

自研 Release 测试生成 600 条快照，按既定的丢弃序列交付 541 条。三次均从原始消息合计 132,682 B 压缩到 28,754 B，客人最终状态与房主相同，双方保留的有效字典载荷峰值为 6,896 B。三次测试的整段进程 CPU 为 62.5、46.875、62.5 ms，其中包含生成、编码、解码、应用和确认。字节统计层级为复制消息。原版的布局字数与自研的消息字节无法用于性能排名。[Core 负载](../../tests/core/codec_workload.cpp)

从 netcode 根目录运行。完整构建命令与本机 SDK 路径见[深化状态](深化状态.md)。本轮 Debug、Release 的既有 11 项核心测试均通过。三引擎轮流当房主的机关样例通过，三局跨端倒计时实际触发跨度为 16、32、40 ms。二维和三维单体预测回归同样通过。

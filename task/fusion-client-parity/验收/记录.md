# 验收记录

本阶段的 `verify_plates.py` 混合引擎实验用于诊断公共 Core。产品验收按引擎分别组房，复跑同引擎玩法时在 `examples` 仓执行 `python -B tools/verify_gameplay_components.py --engine godot`，也可选择 `unity` 或 `cocos`。[运行器](../../../../examples/tools/verify_gameplay_components.py)

改造前参考为[上一轮 M6](../../cross-engine-sync/验收/M6.md)。本目标的实测结果按能力追加。

## Windows x64 核心与进程联机

2026-11-21 在独立 Core Debug 构建运行 `python -B tools/build.py`，改造前和接入通用会话后分别通过全部 7 组 CTest。真实网络使用 `python -B tools/verify_puzzle.py --port 43450`，独立进程通过 TCP 和 UDP 回环通信，退出码 0。测试脚本断言收端状态，原始日志位于轮换目录 `out/runs/last-pass`。

| 能力 | 自研运行观测 |
|---|---|
| 写权交接 | B 断开下行采样期间本地格子 5，公开格子 2。交接后收到上一代次的迟发数据，各端仍保持格子 9。B 和 C 同时申请时 C 收到 Busy。持有者先拒绝再批准，C 释放后房主代次为 6。 |
| 区域和用户分发 | 记分牌进入区域 17 后只对订阅该区域的 B 可见。C 已订阅同编号用户键，重新标为用户键后 C 看见 16777219 分，B 隐藏。重入基线保留字符串 South。 |
| 入局 | 局内第 4 席以旁观者身份收到对象，其写权请求返回 Unavailable。第 5 席晚加入并收到代次 3 的标记物及值 7。第 6 个进程收到 Full。原房间默认四席、开局后锁定和旧局票据隔离的核心回归同时通过。 |
| 时间 | 第 5 席中途入局后获得房主时钟；先后从两个进程读取的局内时间相差 16 ms，包含命令调度时间。此单次观测不能作为公网时钟误差分位数。 |

## 新游戏、对象身份和多模型

`python -B tools/build.py --cocos --godot --unity --parallel 4` 已成功构建三端，Release 的 8 组 CTest 全部通过。运行 `python -B tools/verify_plates.py --port 43470`，退出码 0。三轮都使用同一份 plates.cfg，Cocos 使用场景组件，Godot 使用 GDScript 和 GDExtension，Unity 使用 MonoBehaviour 和 C# 接口。九个进程都检查两块机关的位置分别为 3、7，名字为 Amber、Jade。测试使用真实客户端的无窗口模式，画面美术和手柄操作另验。

| 房主 | 玩家 2 | 玩家 3 | 三端观测 |
|---|---|---|---|
| Cocos | Godot | Unity | 机关 1 写者为 2，机关 2 写者为 3 |
| Godot | Cocos | Unity | 同上 |
| Unity | Cocos | Godot | 同上 |

`tests/core/game_session_test.cpp` 还通过以下确定性检查。

- 两端同时动态抢同一对象，都能先看到临时状态。房主裁决后，输家收到撤销事件，赢家首个动作得到确认。回归修复覆盖客户端预操作步号早于授权起点的情况。
- 对同一客户端生成请求重送两次，房主仅创建一个对象。两个场景里的相同稳定键对应不同对象，重进同一地图能按原键查到新实例。循环挂接和跨地图挂接被拒绝；断开后持票重入恢复父子关系；重载旧地图不会接受旧加载代次。
- 离散棋子和含速度的连续升降台由同一客人同时预测。暂扣下行 6 步（180 ms），逆序释放，各流分别回放和确认到输入 6。换掉升降台的输入归属后，棋子继续执行输入。
- 在区域键重叠时取最快订阅，远近两端的发送频率独立；跨过发送边界的帧仍会送达。取消可靠 RPC 的序号会从控制通道送达，连续丢弃 20 次游戏通道重发后，同一对象的下一条调用仍能执行。另验隐藏对象的 UDP 增量为零、销毁和断线结果。
- 新版快照在能力探测后使用各收端确认的字典。固定的 80 元素列表缩为 76、改一项并改一段字符串后，同一份普通快照为 453 B，紧凑快照为 56 B。浮点按 0.25 量化，误差小于 0.125；旧端保留原浮点；缺少字典时拒绝解码并请求重建。此项数据来自独立 Debug 构建的新增断言。

## 原生二维刚体

构建命令为 `python -B tools/build.py --cocos --godot --unity --parallel 4 --chipmunk-root ../cocos2d-x-4/cmake-build-headless/Chipmunk2D-Chipmunk-7.0.1`。联机命令为 `python -B tools/verify_plates.py --forecast --port 43476`，退出码 0。测试分别使用 PhysicsBody、RigidBody2D、Rigidbody2D，读取引擎的真实碰撞事件和休眠标志。

房内刚体以 3 m/s 向墙运动，第一次接触后休眠，传送到 8 m 处，以 0.5 m/s 唤醒，随后再次休眠。三轮中九个进程各自观察到接触、休眠、唤醒和最终休眠。以 Cocos、Godot、Unity 为房主时，各轮三个进程最终位置分别同为 8359、8358、8360 mm。输入条件与结果记录单位固定；引擎逐步碰撞轨迹并非逐帧一致性验收。

## 最终本机验收

Windows x64，所有玩家进程通过回环地址联机。通用 Core 在 Debug 独立构建；三个引擎在 Release 构建，Cocos 启用上文的 Chipmunk 依赖。测试按场串行执行，原始进程日志使用仓库规定的轮换目录。下表给出最后一次对应场景的通过条件和读数。

| 用例 | 运行或观测 |
|---|---|
| 构建和独立核心 | `python -B tools/build.py` 在 Debug 通过 10/10 组 CTest。上文三引擎物理构建命令在 Release 通过 10/10，生成三个引擎的运行产物。最终配置中的 `NETCODE_STEAM` 为 OFF。 |
| 本地发现与票据 | `lan_directory` 用回环多播公告两间房并按区域、版本、属性找房。客户端连接返回的端口，房主拒绝最后一席的迟到竞争者。已占满的房间里，原玩家通过含满员房间的目录查询和重连票据恢复原席、原局。另一房间停止公告后从目录过期。 |
| 三端玩法和时间 | `python -B tools/verify_plates.py --port 43470`。三个房主均先发布地图 1。客人按资源名确认代次，随后通过键 100、200 读取机关。九端检查名称、格子和写者。截止时间 3200 ms，以 Cocos、Godot、Unity 为房主时三进程日志触发跨度分别为 28、22、33 ms，门槛 250 ms。这是含进程调度的本机结果。 |
| 两模型、权威和层级 | `game_session` 覆盖升降台和棋子在 180 ms 暂扣下行、逆序恢复后独立回放。附属对象随持有人离线销毁，父对象退出兴趣范围时屏蔽子对象字段及元数据，重入后父子身份恢复。`migration_quorum` 另验证全局模板只能生成一份并随房主接替。 |
| 字典重建 | 丢弃收包字典确认直到旧锚点已被接收方淘汰。实际会话收到重建请求后改发自包含快照，后续状态再次收敛。固定数据集 453 B 和 56 B 的对照沿用上文。 |
| 真实房间与观战 | `python -B tools/verify_puzzle.py --port 43450`。下行暂扣时本地值 5、公开值 2，换写者用时 99 ms，重入读回 16777219。第 4 席旁观、第 5 席晚入、第 6 席收到满员拒绝。顺次读取两个时钟相差 24 ms。独立 `room_processes.py` 也通过房间、票据和心跳回归。 |
| 原生二维刚体 | `python -B tools/verify_plates.py --forecast --port 43476`。九个进程均观测到原生接触、休眠、唤醒及第二次休眠。本轮以 Cocos、Godot、Unity 为房主时，同轮三端的最终位置分别为 8359、8349、8360 mm。 |
| 房主强制退出与目录更新 | `python -B tools/verify_migration.py --port 43490`。热备保存到第 20 步后强制结束玩家 1。玩家 2 接任，玩家 3 恢复原席位。世界仍在第 1 局，地图 7、键 701 的物体仍挂在原父节点下。写权代次为 2，双方先恢复 77，再共同观察到 88。自强制退出到再次确认写入共 1782 ms，浏览器同时读到同一房间的新端口 43491。同一位客人在迁移前后各给棋子和升降台输入一次，最终格子 7、台面高度 3000 mm。两个对象分别确认到输入 2，房主与客人完全一致。 |
| 迁移故障回归 | 原房主默认持有且从未转权的 PlayerAttached 对象也会在迁移时销毁，全局对象随任期转交。曾观测到候选人已接任、客人已重入却收不到地图基线。修复接任后仍保留旧连接断开标记的问题，并在重入基线就绪前保留已恢复的写权。可控时钟测试另检查较长暂停后的旧房主停止工作、少数派不产生新房主、截断检查点被完整拒绝。 |

房主接替针对一次热备交接。可恢复的进度以热备收到的完整检查点为准；飞行中的可靠调用和检查点后的动作可能需要由业务补偿。二维刚体验证涵盖接触与纠偏，三维多刚体或关节的完整物理回滚仍需单独验收。本轮跳过 Steam 与公网跨机。

## 车场回归

每种房主和客人组合都运行类型化配置，共九组。六个异构组合都开启丢包、重复与乱序。三个同引擎组合另外运行一次客户写权的接管和重连，共十二组双进程联机。每组冻结后的双方摘要一致并正常退出。下表单元格是客人带原票据恢复原车的时间，包含测试指定的 1050 ms 离线间隔。

| 房主 | Cocos2d-x 客人 | Godot 客人 | Unity 客人 | 同引擎客人写权 |
|---|---:|---:|---:|---:|
| Cocos2d-x | 1183 ms | 1216 ms | 1233 ms | 1183 ms |
| Godot | 1200 ms | 1216 ms | 1199 ms | 1233 ms |
| Unity | 1200 ms | 1199 ms | 1250 ms | 1249 ms |

四人压测每轮驱动 10 秒，活动对象包括 4 辆车及 96 个其他对象。故障数为四端总和，摘要比对涵盖全部对象和字段。

| 写权配置 | 玩家 / 对象 | 丢弃 / 重复 / 乱序 | 四端一致的摘要 | 结果 |

| 房主结算四辆车 | 4 / 100 | 184 / 256 / 229 | `12918851976728775203` | 四端冻结后完整字段一致 |
| 两客人持权、其余房主写入 | 4 / 100 | 181 / 252 / 229 | `12272630517614032386` | 557 次提交，房主接纳 350 次，重连 1200 ms |

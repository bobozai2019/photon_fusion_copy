# 客户端框架深化验收

续验的脚本房主接替、多体回放、原版编码负载见[余项验收](余项验收.md)。下表保留上一轮测试条件和数字。

[逐项对照基线](Fusion逐项对照.md) · [本轮范围](深化计划.md)。Fusion 对照使用前述报告列明的手册契约和 Godot Preview 555 观测。以下命令运行自研实现，端口仅限本机。最终各房主数字见[本机测试数据](验收/深化本机.json)。

| 能力 | 当前可复查的结果 |
|---|---|
| 对象模式和 RPC | Core 同模板生成不同模式，A→B→A 迟到指令按写权代次拒绝。Cocos、Godot、Unity 轮流作为房主，每局收到玩家 2 对对象 1 的值 3 和玩家 3 对对象 2 的值 7。两位发送者各收到带原令牌的逐目标回执。 |
| 对象身份 | 支持按地图和作者键实例化全局对象；检查点保留对象模式。两位客人同帧在房主处理前取得可传递的引用，房主依工厂策略确认为不同对象，基线确认后自动授予写权。未授权工厂拒绝创建；重入使用新命名空间且仍可解析旧的存活对象。 |
| 父子可见性、时钟、席位 | 最终 Debug、Release 各 11 组 CTest 全部通过。GameSession 覆盖子对象独立筛选和继承，时钟单测含上下行不对称、缓慢纠偏、大偏移跳时。Room 以可控时钟验证席位 TTL 临界点并拒绝过期票据。 |
| 预测和脚本 | 三个房主轮换，三个引擎也都各当过输入玩家。脚本开启独立充能模型与区域键 81；输入者即时读到 5、收到序号 1 的确认、三端最终复制值均为 5。最终一轮 3.2 秒倒计时进程日志跨度为 23、38、34 ms。 |
| 地图与代次 | Cocos 用异步文件读取，Godot 异步加载 PackedScene，Unity 异步加载 Prefab。三种房主 × 三个引擎均挂载非空地图 1；地图 2 的代次 2 在挂载前取消，代次 4 仅挂载一次，卸载时移除。Core 验证整图替换的错误参数对旧图无副作用，成功后持久对象仍在。 |
| 匹配与接替 | 局域网回归覆盖属性过滤、随机选择匹配房及无匹配结果。真实三进程 `verify_migration.py --chain --port 43490`：强杀首任房主，后继在 1811 ms 内完成恢复和写入，值 77→88。两人局第二任房主正常交接，最后一人任期 3，先恢复 89，再写到 90。 |
| 编码 | Release 的 `codec_workload.exe` 发送 600 帧、接收 541 帧。输入快照 132682 B，编码 28754 B，发送和接收端常驻字典载荷容量峰值合计 6896 B。本次墙钟 124561 µs、进程 CPU 125 ms，数值包括复制和校验。没有采到 Fusion 在相同数据及确认节奏下的字节或 CPU。 |
| 引擎编辑器与原生物理 | Godot 无窗口探针和 Unity 构建各从场景实际属性导出相同的 23 号模板（vec3 position），交给同一 Core 验证。二维、三维各跑三局，轮换房主；代理依次发生原生接触、睡眠、传送、唤醒、再次静止。三维校验额外检查深度及朝向。公网与 Steam 按本轮约定跳过。 |

已有样例回归另外跑了三进程机关和四人百对象车场。车场注入丢包、重复与乱序，测量窗口 10023 ms，301 个物理步、200 次发送步，四端最终摘要均为 17736340503273206716；重连 1216 ms，三次写权切换观测为 36、32、74 ms。100 个对象中有 4 辆车。

复现使用 `python -B tools/build.py` 和三引擎 Release 构建后的 `python -B tools/verify_plates.py --port 43470`。测试源在 [game_session_test.cpp](../../tests/core/game_session_test.cpp)、[room_test.cpp](../../tests/core/room_test.cpp) 和 [verify_plates.py](../../../examples/tools/verify_plates.py)。

## 13 项与 Fusion 能力的关系

| 项 | 本地已验 | 适用条件与剩余差异 |
|---|---|---|
| 1 引擎接入 | C#、GDScript、C++ 各自承载相同的预测、RPC 和兴趣订阅。Unity 与 Godot 能将场景属性导出为通用布局。 | 作者选择稳定字段号与容量。编辑器自动生成的代码、诊断和调试工具链仍有差距。 |
| 2 实例权威 | 同模板不同写权模式，房主授权与撤权，按代次挡住旧指令，客人创建时可申请初始写权。 | 房主仍掌握名册、工厂与路由。新创建者须等基线得到确认后写公共状态。 |
| 3 身份与寿命 | 即时创建引用、按地图与键查找、附属对象随玩家处置、重入后解析仍存活的旧引用。 | 动态引用只在对应局内有效；本机对象号随可见基线到达后可用。原版动态 ID 的组成不同。 |
| 4 场景 | 整体换图、多图叠加、非空资源异步挂载、取消旧代、卸载节点、隔离未就绪对象。 | 玩法负责资产映射与挂载。跨引擎测试使用同一逻辑资源名，各引擎载入自己的资源。 |
| 5 预测 | 60 个输入，房主执行 60 次且无重复；预测者回调 70 次，收到 15 次有效基线，共确认 60，最终和 1830。 | 自研试验每 6 输入暂扣并倒序释放下行；555 原版三轮房主均消费 60 次，预测回调 434–544 次。网络节奏不同。回调次数不能用于性能排名。 |
| 6 网络时钟 | 90/10 ms 非对称样例测出半 RTT 估计的 40 ms 偏差；分段时钟处理 0.10/0.25 秒阈值、±1/60 调速与跳时。 | 阈值参照 555；样本来源、采样频率与线上服务不同。持续单调模式仍是默认选项。 |
| 7 兴趣管理 | 脚本订阅区域及玩家键，根与挂件可共用分发频率，可单独限制子对象。重连保存订阅。 | 未测与原版在相同大世界、相同曲线下的 CPU 和带宽上限。 |
| 8 RPC | 业务归属、状态写者分别门控；可靠/尽力投递、目标筛选、变长参数、逐收件结果。脚本端可以追踪令牌。 | Received 表示对端通道确认。样例另在房主业务处理函数记录实际发送者、对象与载荷。 |
| 9 编码 | 九种带类型字段及每接收者确认字典，变更/丢包工作负载有字节、时间、字典尺寸与最终状态校验。 | 自研线格式、字符串表示、内存布局不同；保留载荷容量不含分配器和表节点。本轮已核对 Preview 684 的同输入最终摘要，原版网络字节与编码 CPU 仍缺可比样本。[编码对照](余项验收.md)。 |
| 10 原生刚体 | 三引擎的 2D/3D 原生体有速度、力、混合校正和可配外推期。每局测 0.35、0.50、0.65、0.80 秒四个运动中位置，另验接触、传送、休眠。 | 本机三种房主下，最终一轮二维最大采样差 113 mm，三维 98 mm；同一局末态三端取整相同。误差只涵盖这些时点。本轮新增三维双箱堆叠、两体固定关节和四体组回放。[九种引擎组合及误差](余项验收.md)。更长的关节链、二维多体和原版同场景轨迹仍待验证。 |
| 11 准入与重入 | 满员、旁观、迟入、短 TTL、到期前持票恢复、到期后拒旧票和普通新席位。 | 房间服务由在线房主提供。所有玩家退出后，房间的云端保活需要另有承载。 |
| 12 房主接替 | 真实三进程经历三任房主；网络分区测试保留多数派规则，暂停的旧主恢复时被禁止继续工作。 | 突然强退恢复到成功传完的检查点，可能丢失其后的未确认更改。两人正常交接要求旧主在线且新主已准备监听。上一轮从 C++ 入口验收。本轮已接通 Unity C# 和 Godot GDScript 的 NetcodeGame，两种引擎轮换顺序见[余项验收](余项验收.md)。 |
| 13 发现匹配 | LAN 房间公告、属性与区域标签筛选、随机匹配候选、抢最后一席，接替后端点可更新。 | 区域是 LAN 房间属性。Photon 的公网区域调度、身份认证和云目录依赖外部服务；按用户约定跳过 Steam。 |

复现三引擎刚体与接替使用以下命令。在 netcode 仓库根目录运行，完整三维构建需要本机 Cocos 使用的 x64 Bullet 与二维 Chipmunk 源码。

```powershell
python -B tools/build.py --cocos --godot --unity --parallel 4 --chipmunk-root ../cocos2d-x-4/cmake-build-headless/Chipmunk2D-Chipmunk-7.0.1 --bullet-root ../cocos2d-x-4/cmake-build-headless/3d/bullet-install
python -B tools/verify_plates.py --port 43470
python -B tools/verify_plates.py --forecast --port 43476
python -B tools/verify_plates.py --forecast3d --port 43480
python -B tools/build.py
python -B tools/verify_migration.py --chain --port 43490
```

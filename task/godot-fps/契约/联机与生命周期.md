# 房间、玩家与地图状态

下表描述 Shiftline 游戏契约。房间协调、字段采样和传输沿用现有插件。玩法实现位于 [Shiftline 对局脚本](../../../../examples/shiftline/net/match.gd)，入口是[主场景](../../../../examples/shiftline/app/main.tscn)。

## 现有插件接入点

| 现有行为 | 依据与实现影响 |
|---|---|
| 房间容量默认 4，可显式指定。Godot 的打开入口启用扩展加入和开局后加入 | 房主与客人都传容量 8。用同构建的 1 主 7 客验证，不能以参数校验代替满房实测。[Godot 绑定](../../../engineplatform/godot/game.cpp) |
| 一个 NetcodeRoom 可以同时登记场景根和动态模板，按相对节点路径绑定场景对象 | 每端先实例化同一仓库根、八个固定玩家槽位、比赛状态和地图物件；将手榴弹列为动态模板。同一会话只有一个驱动执行 advance。房主生成静态复制对象，动态实例在各端按对象 ID 绑定及释放。[房间实现](../../../engineplatform/godot/scene_room.gd) |
| 房主可取得已就绪的房间成员。routing_info(0, true) 的 audience 是房间级列表，含房主；seats 只有数量 | 房主用就绪成员分配和回收槽位。房间进入运行阶段前设置 player TTL 为 0。正常退出与网络超时都触发名额回收。名单的昵称、队伍和 K/D 取自相应玩家槽位。[Godot 绑定](../../../engineplatform/godot/game.cpp) · [席位寿命](../../../core/session/room.cpp) |
| 复制字段会给新成员当前值；RPC 只通知当时在线的目标；单条 RPC 业务参数预算 220 字节 | 比分、弹药、人物状态、破箱、补给、仍在飞行的手榴弹都可从当前对象恢复。曳光、命中标记和一次性音画效果可用短事件。G1 校验字段布局，G3 校验同时收发及编码大小。[场景同步规格](../../../docs/specs/godot-scene-sync.md) |

## 房间与成员

1. 大厅输入昵称、主机监听地址或客人目的 IPv4、端口 1–65535。默认选可用 LAN IPv4；多网卡时允许选择。顶栏展示客人实际可填的地址。保留回环地址供同机测试。
2. 各端先创建同一场景根，登记房间 RPC，调用 `room.open(root, host, address, port, 8, templates)`。房主在等待阶段调用 `room.game.set_player_ttl(0)`，随即 `start()`。房主先让固定对象的首次绑定采样完成，再分配成员和写入资料。两端都等基线与本人槽位可用才接管相机和输入。连接中有可见反馈与取消入口。
3. 房主按已就绪成员创建占用关系，尽量分入人少的一队，每队上限 4。平局时轮流分队。昵称和网络身份分开，重名也能辨别玩家。玩家离开释放槽位和角色，清理输入、复活计时与人员行；同端再次加入按新成员处理。旧玩家离开后已取得的队伍分数保留。
4. 原生房间在整场游戏期间保持运行。玩法单独使用 `match_id` 区分对局。达到 30 分时仅房主结算一次，短暂展示胜方，原房自动开启下一局；所有仍在线的成员保留队伍。结算期间加入者先看当前结算，再和全员一起出生。
5. 主动退房或房主失联后释放全部场景、连接和输入捕获，显示可操作的大厅和原因。原生返回明确错误时据此显示；若只观察到连接超时则提示地址、端口与连接状态，允许原地重试。房主迁移不开启。

## 房主维护的复制字段

| 对象与身份 | 字段（拟定的 Godot 类型） | 生命周期与使用方 |
|---|---|---|
| Match，一间房一个 | match_id: int，phase: int（进行中／结算），score_a、score_b: int，winner: int，restart_at: float，host_ip: String，port: int | 房主写，顶栏与结算读。计时统一用插件房间时钟秒数。胜负冻结后到期切换新 match_id。 |
| PlayerSlot，地图预置 8 个稳定槽位 | slot_index、player_id、life_id、match_id、team、hp、kills、deaths、magazine、reserve、grenades、pose、action、action_seq、ack_input_seq、ping_ms: int；nickname: String；active、alive: bool；position、velocity: Vector3；yaw、pitch、action_until、respawn_at: float | 空位关闭显示与碰撞。新占用者重置字段；复活使用新的 life_id。人物渲染、计分板和 HUD 订阅同一状态。ping_ms 采自该玩家到房主的往返时间，房主为 0，尚无样本显示“—”。 |
| Crate，对应地图中的固定位置 | map_id、match_id、hp: int，destroyed: bool | 本局打碎后模型、碰撞和射线遮挡同时关闭；开新局恢复。固定掩体独立于木箱。 |
| Pickup，一个地图补给点 | map_id、match_id、kind、generation: int，available: bool，refresh_at: float | 领取后同一代只结算一次。到期恢复并递增 generation。木箱和拾取物的名称／路径在各端一致。 |
| Grenade，每次成功投掷一个动态对象 | 使用插件对象 ID；match_id、thrower_id、thrower_team: int，position、velocity: Vector3，detonate_at: float | 房主模拟飞行、碰撞与爆炸，客人显示轨迹。晚加入时显示当前位置；引爆后统一移除。保留投出时的队伍；投掷者已离开仍可结算有效队分。 |

连续姿态和位置做插值，复活、换槽和切局立即应用新基线。每个对象携带 match_id；客机丢弃上一局动作。场景开放本机输入前，核对比赛、本人角色和预置交互物件的基线已到齐。角色、物件、人员表每行均有稳定身份，以便连续进退和复用槽位。

## 玩家输入与反馈

所有玩家共用同一个房主规则处理函数。房主本人的输入走本地调用；客人用房间 RPC 发给 TARGET_MASTER，房主从 get_rpc_sender() 取得身份。动作和命中均有对局与生命代次，玩家只提交操作意图。

| 拟定接口 | 载荷、方向与投递 | 处理结果 |
|---|---|---|
| set_profile | 客 → 主，可靠；nickname: String，限制 32 UTF-8 字节 | 房主绑定实际发送者，一次验证昵称后写回本人槽位；空昵称给可辨识的默认名。 |
| move_input | 客 → 主，不可靠；match_id、life_id、seq、buttons: int，move: Vector2，yaw、pitch: float | 房主仅接受当前生命的更新序号，校验输入范围并在角色物理步移动。ack_input_seq 记录最后处理的输入。输入中断后自动归零。远端插值，本地视角随鼠标即时更新。 |
| action_request | 客 → 主，可靠；match_id、life_id、seq、kind、target_id、generation: int，aim: Vector3 | kind 含开始／停止开火、换弹、投掷、拾取；拾取需指定物件与刷新代次。房主检查存活、动作冷却、弹药及交互范围，按发送者与序号去重。松开射击键、窗口失焦或打开菜单时停止连续开火。 |
| action_result | 主 → 原请求者，可靠；match_id、life_id、seq、result: int | result 包含已接受、无效生命、资源不足、动作冲突、目标已消耗等。相同请求返回既有结果；库存和伤害以复制状态为准。 |
| shot_fx | 主 → 在线观察者，不可靠；match_id、shooter_id、shot_seq: int，起止点: Vector3；命中类型: int | shot_seq 在同一房间内递增。观察者过滤旧局与旧序号后显示曳光，射手从同一事件取得命中反馈。房主射线从权威角色位置出发。 |
| blast_fx | 主 → 在线观察者，不可靠；match_id、blast_seq: int，center: Vector3 | 客人显示爆炸。late join 的飞行物从复制对象恢复，已经爆炸的物体及一次性事件不会补播。 |
| report_ping | 客 → 主，低频不可靠；ping_ms: int | 客人将 frame.rtt 由秒换算为毫秒。房主按发送者更新人员表的展示字段。 |

### 游戏规则与待调参数

- 步枪采用游戏射线判定，按住连发，枪口曳光表现弹道。房主负责扣弹、计时换弹和击中反馈；手榴弹采用可见的 3D 投掷物。出生带一把步枪和一枚手榴弹。
- HP 首次归零时结算一次阵亡与有效击杀。队友互不扣血。实现默认本人也不受自己手榴弹伤害；敌方击败加 1 队分。第 30 分立即锁定胜方和队分。房主计满 3 秒后在本队空闲出生点复活；切局取消旧倒计时。
- 木箱可受步枪与手榴弹的游戏伤害，打碎后该通路可用。补给只在能增加库存时消耗；同时领取时，先被房主接受的请求获物。新局恢复箱体、所有补给、人物初始库存、个人 K/D 和队分，并清掉旧投掷物。
- 总人数 8、每队 4、复活 3 秒、胜分 30。试玩参数放在 `net/config.gd`。步枪 30 发弹匣、90 发初始备弹、1.75 秒换弹；补给 12 秒刷新，结算显示 6 秒。
- 房主与客人共用权威移动输入。客人即时更新视角，位置跟随权威快照并做呈现插值。ack_input_seq 用于序号拒绝与观测，当前没有位置预测回演。

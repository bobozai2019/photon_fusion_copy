# Godot 3D 局域网 FPS 执行计划

玩家在 Windows 上打开游戏，输入昵称后可直接 Host，或填入房主的 IPv4 和端口 Join。房主独自进图即可移动、试射、投掷和拾取。第一个客人加入即可交战，最多 4 对 4。整局都允许进出，房主离开即结束房间。

需求于 2026-11-22 经两轮访谈确认。独立工程命名为 **Shiftline**，可以从 Godot 编辑器运行，也已产出 Windows x64 包。交付验收采用 Windows x64 同机独立进程和干净解压启动。[执行状态](执行状态.md) · [资产清单](资产清单与制作计划.md) · [联机契约](契约/联机与生命周期.md) · [验收计划](验收计划.md)

## 工程落点

当前目录如下，路径相对于两个仓库的共同父目录。Shiftline 的启动与导出命令见[工程 README](../../../examples/shiftline/README.md)。

```text
examples/shiftline/
  project.godot             F5 进入大厅
  app/                      会话入口、场景切换
  ui/                       大厅、顶栏、战斗 HUD、人员表、菜单、结算
  net/                      房间生命周期、输入 RPC、复制字段
  arena/                    仓库、出生点、梯子、箱体、补给点
  actors/                   玩家控制器、手臂和全身动画、武器和投掷物
  assets/                   模型、材质、动画、许可和来源清单
  export_presets.cfg
  README.md                 插件准备、F5、开房与按键
examples/tools/             FPS 工程准备、联机复验及 Windows 打包入口
netcode/task/godot-fps/验收/  G1–G6 报告及 V1–V8 实测结果
```

基线采用仓库已有 Windows Godot 4.7.1 配置、GDScript 和自研 Netcode 插件。规划用现有插件包准备独立工程，插件脚本和 DLL 来自同一构建。源码工程的首次准备、编辑器直接 F5 和解压包启动都要验证。参考[插件接入手册](../../docs/specs/godot-scene-sync.md)、[构建与导入工具](../../tools/godot_build.py)和[插件打包入口](../../tools/package_godot_addon.py)。

## 实现顺序

| 任务 | 依赖 | 交付物与完成条件 |
|---|---|---|
| T1 房间与垂直切片 | 起点 | 新工程、可操作的大厅和单房间驱动。两个独立进程从正常入口进入灰盒，看见彼此的角色及进退变化；房主退房可恢复大厅。接着用 1 主 7 客提前验证容量。 |
| T2 仓库与骨骼资产 | 与 T1 同时起步；和 T1 约定角色尺寸与输入名称 | 8 个模型已导入。先用现有手臂、步枪、全身士兵完成双视角换弹，再制作仓库模块、交互物和遗漏动作。用同一角色胶囊从两边走通两层。[逐件交付清单](资产清单与制作计划.md) |
| T3 对局与权威状态 | T1 | 房主处理移动输入、命中、投掷、道具争用、计分、阵亡及重开；晚加入者获得比分、人物和地图道具的当前状态。灰盒环境用双端、三端先验规则。 |
| T4 场景与战斗表现集成 | T2、T3 | 把双视角和地图接到真实联机人物，统一碰撞、梯子、动画和投掷物。以两个可视客户端验收双方实际看见的动作、木箱打通和再次复活。 |
| T5 界面与生命周期 | T1 后可做布局；定稿依赖 T3 | 大厅与联机错误、房间顶栏、人员表、战斗 HUD、退出菜单和结算。跨离房、重开和 UI 隐藏时验证鼠标捕获、Esc 恢复和名单清理。 |
| T6 Windows 交付 | T4、T5 | 提供 Win x64 解压包、玩法说明、资产清单和可复跑的多进程验收。用干净解压目录验证独立启动、同机开房和加入，并记录包校验值。 |

T1 负责房间驱动和主场景入口，T2 负责资产和关卡，T3 负责对局规则与复制对象，T5 负责 UI。T4 合并角色场景和输入映射，统一检查碰撞层、动画事件、退出清理。输入字段、场景根路径或资源标识发生变化时，先更新契约及依赖用例。

## 运行方式与阶段门槛

| 环境 | 操作 | 检查目的 |
|---|---|---|
| 开发机编辑器 | 准备插件，在独立工程按 F5，Host 后即进图 | 日常操作、地图与动画调试 |
| 同机多进程 | 在独立进程从大厅连到 127.0.0.1；主客加晚加入端；人数测试开 1 主 7 客，另起第 9 个实例 | 核对规则、状态一致性、边界和重复操作 |
| Windows 解压包 | 在干净目录启动两份可视 EXE，经本机回环 IPv4 和所选端口 Host、Join | 验证发布包独立启动、可见画面、开火及退房恢复 |

- [x] **G1 房间能玩。** F5 后房主独自可移动，第二个进程可加入、退出、再进。8 人满房后可释放席位。[结果](验收/G1.md)
- [x] **G2 地图与模型可用。** 用角色实走两边的上下路线，导入资产能在第一、第三人称各完成一次换弹。[结果](验收/G2.md)
- [x] **G3 对局能复现。** 客人能击败房主。禁友伤、并发拾取、破箱、晚加入、30 分结算与原房第二局通过状态断言。[结果](验收/G3.md)
- [x] **G4 画面与操作一致。** 同机的两个可视窗口复现动作、投掷、碰撞与结果。[结果](验收/G4.md)
- [x] **G5 UI 能恢复。** 在大厅、对局、结算和房主断开时走完 UI 用例。[结果](验收/G5.md)
- [x] **G6 可交付。** V1–V8 均有结果。记录同机容量、干净解压启动和发布包同机双开的实测环境、构建与包校验值。[结果](验收/G6.md)

复跑命令、Windows 包位置和按键见 [Shiftline README](../../../examples/shiftline/README.md)。各门槛的实测结果见 [执行状态](执行状态.md)。

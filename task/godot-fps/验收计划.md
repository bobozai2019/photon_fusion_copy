# 验收计划

下列用例在 FPS 实施阶段运行。每次记录构建标识、插件版本、运行命令、进程角色、预期和实测。涉及显示与操作的断言使用可见窗口；状态一致性另用独立进程断言。实际结果按 G1–G6 写入本任务的 `验收/` 目录。

| 用例 | 操作 | 通过条件 |
|---|---|---|
| V1 大厅、直连和错误恢复 | A 从主菜单点 Host，B 输入 A 顶栏的 IP 和端口 Join。再试一次占用端口、非法端口、不可达地址及连接中取消。 | A 可独自进图活动，B 加入现有场景，双方人数由 1/8 变成 2/8。没有“等待房主开始”的额外操作。错误或取消后按钮可用，可以成功重试。 |
| V2 中途进退 | A、B 进入对局，C 在对局中加入，B 正常离开后重进，再强制关闭 B。最后分别测房主点退出、房主进程被关闭。 | 各端名单、队色和角色数量一致。B 被回收，旧角色、碰撞和复活计时消失；重进只出现一个新角色。房主退出或超时后所有客人收到提示，恢复可用大厅，能再次开房。 |
| V3 地图与人物 | 两名玩家分别从各自出生区走地面路线，穿过侧房，从楼梯上二层、经走廊从直梯下，再反向爬上。观察第一人称手臂和远端整个人物。 | 两侧都能完成两条路线；楼梯连续可走、梯顶能离梯，蹲伏和固定掩体碰撞有效。能看清队色、手持武器和角色轮廓。角色有 Skeleton3D、蒙皮和实际可播放的动画；第一人称镜头内手臂跟随视角，远端能辨待机、跑动、蹲伏、爬梯。 |
| V4 武器、死亡与复活 | B 对 A 连续射击至弹匣空、换弹、再次开火；另测命中队友、两人同时命中同一低血量对手、投掷和阵亡后重入场。录两端画面，并核对房主状态。 | 步枪有曳光、命中反馈；空弹停止，换弹后可继续射击。手榴弹从手中投出，两端能看见飞行、落地、爆炸。手臂能展示开火、换弹、投掷；远端全身另有阵亡动作。友军无伤害，单次死亡只得 1 分。复活时刻为房主判定死亡后 3 秒（允许一个房主物理步的调度误差），客人随后显示复活。 |
| V5 道具、碰撞与晚加入 | A、B 同时按 E 取同一补给；取走手榴弹补给，把挡路的木箱打碎。C 在刷新前入房。另在有飞行中投掷物时加入，并让一个玩家在投出后退出。 | 同代补给只发一份，三端对弹药包与手榴弹补给的可用性和刷新结果一致。C 能穿过碎箱处，固定掩体依旧阻挡。飞行中的投掷物位置与剩余时间对应当前现场，已爆炸的投掷物不会重放；投掷者离开也只引爆一次。 |
| V6 结算与第二局 | 第一局取得有效击杀，C 加入后核对 K/D、比分和存活状态。到 29 分后让两个有效命中紧邻发生，另一个客人在结算期入房。全程保留原连接。 | 以正常击败完成第 30 分，只显示一个胜方。所有人看到同一结算，再进入同房第二局；人数和队伍正确，比分、K/D、库存、木箱和补给已重置。旧复活和投掷计时不会影响新局。 |
| V7 容量与席位 | 1 主 7 客占满房间，尝试第 9 人加入。关闭一个客人，再让第 9 人加入。重复更换成员并移动、射击和领取补给。 | 满员时各端显示 8/8、每队 4 人，名单与场内实际人物一一对应；第 9 人未获席位。离开被检测到后可补位到 8/8。原成员的角色、库存和成绩未串到新成员。记录满房过程中延迟样本与进程错误。 |
| V8 UI 与 Windows 交付包 | 在一台 Windows 电脑的干净解压目录启动两份可视 EXE，经 IPv4 开房和加入，开火并退出房间。用同机可视对局覆盖双方交火，大厅、对局和结算的 F1，以及 Tab、Esc、鼠标释放和重新捕获。在隐藏 UI 时模拟房主退出。 | 顶栏有实际 IP、端口、人数和比分。Tab 开关人员表，五个字段齐全。F1 隐藏当前全部 UI（含准星），再次按 F1 恢复先前面板可见性。Esc 可从隐藏状态打开菜单。大厅或断开提示可操作，菜单内点击不会开火。解压包可独立启动，许可、说明、资源和插件随包齐全。 |

## 执行入口与证据

G1–G6 已完成同机复验。V8 的界面证据来自可视客户端，交付证据来自修正版的干净解压启动和同机双开。[执行状态](执行状态.md) · [原始样件实测](验收/资产样件.md) · [最终导出结果](验收/G6.md)

以下命令从同级 `examples` 仓库根目录运行。

```powershell
python -B tools/artifacts.py usage
python -B tools/prepare_godot_fps.py
python -B tools/verify_godot_fps.py
python -B tools/verify_godot_fps.py --visible
python -B tools/package_godot_fps.py
```

准备脚本默认从 [SDK 锁文件](../../../examples/sdk-lock.json) 选择 `netcode-godot-win-x64.zip`，校验 SHA-256 后导入工程。用 `NETCODE_PACKAGES` 指定发行包目录，或给 `prepare_godot_fps.py --addon` 指定要测试的 ZIP。历史验收使用的包和哈希见各阶段记录。[查找与校验](../../../examples/tools/sdk_inputs.py) · [安装入口](../../../examples/tools/prepare_godot_fps.py)

T1 建立 `tools/verify_godot_fps.py`，沿用赛车示例“多进程驱动正常入口”的方式，G6 时在工程 README 固定实际复现命令。自动化通过真实大厅控件或相同输入处理路径触发玩法；每个阶段从房主、客人和晚加入端分别读取状态。报告区分首次快照、变化期和最终一致的结果。截图取自主客可见窗口，重点留第一人称持枪、远端骨骼动作、破箱后通路及满员人员表。

T2 保存每份第三方资产的名称、作者、原始链接、许可文本、归属要求、修改和工程路径。优先选择同套低多边形资源，在 Godot 里检查比例、骨骼蒙皮、武器附着、动作切换及两队配色。资产许可或骨架无法满足交付时改用 Blender 制作，保留可编辑源和导入用 GLB。G6 在干净解压目录检查最终包与清单对应，并记录同机多进程结果。

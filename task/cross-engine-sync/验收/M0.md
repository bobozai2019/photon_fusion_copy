```powershell
python -B tools/artifacts.py usage --reserve-mib 4096
python -B tools/artifacts.py clean
python -B tests/integration/test_artifacts.py
python -B tools/build.py
python -B tools/build.py --cocos
& ./out/build/win-x64/Release/bin/Release/netcode-yard.exe --smoke
```

Cocos 上游桌面依赖中 GLFW 和 GLEW 的 `dumpbin /headers` 均为 `14C machine (x86)`。构建脚本核对官方 `metal-support-22` ZIP 的 SHA-256 `721c0588f10c7e445d4b4103efcf3869203fffa9bf7836deb3c6bb51b2f8a764` 后提取所需源码。GLFW、GLEW、FreeType、PNG、zlib 通过固定基线的 vcpkg 构建 x64 版本。应用选用原 Cocos 4 的桌面渲染和节点模块，关闭音频、引擎网络、Win32 EditBox、编辑器和内置物理。应用的 PE 头为 `8664 machine (x64)`。

初跑出现一个 GLSL 程序链接错误。上游 POSITION 的顶点 shader 输出位置，片元 shader 读取顶点颜色。适配构建给这个组合接上已有的顶点颜色 shader，改动只写入构建目录。Intel UHD 630 上复跑空场景和绑定测试均退出 0，日志没有该错误。双窗口实测了文本、2D 图元和 Sprite3D。[车场画面](M3/车场.png)

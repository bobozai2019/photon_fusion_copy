# Cocos2d-x 联机框架 · 首版执行计划

**规划已定稿，实施和实测见[执行状态](执行状态.md)。** 目标产物为可移植 C++ 核心、首个 Cocos2d-x 4 接入、可玩的 Windows x64 俯视小车场、真实协议轻量客人和复现工具。实施时以本文件的里程碑为准，产品决定可回溯至[访谈总纲](总纲.md)。

## 范围和运行模式

| 类别 | 本轮承诺 |
| --- | --- |
| 核心与连接 | `core/` 可独立构建，连接模块单独可替换。首个直连后端以 TCP 管理房间、UDP 承载输入、复制和 RPC；房主决定最终状态 |
| 引擎与玩法 | `engineplatform/cocos2dx/` 加载声明式配置。两名玩家驾驶、开门、生成和销毁路障，场内有同步的 3D 展示物；2D 和 3D 的位置、旋转、缩放均有回归 |
| 验收环境 | 本机两个真实 Cocos 进程可玩；压力模式保留这两个进程，添加两个轻量客人，形成一个房主、三个客人、100 个同时参与复制的网络对象。三位客人使用同一正式协议 |
| 扩展边界 | 地址和端口可配置，设计支持局域网及跨设备。纯 TCP、Steam P2P、自研 P2P 预留后端接口。Windows 双设备实测另记；第二引擎、编辑器工具、本机预测、历史 RPC 重放留待后续 |
| 参考环境 | 独立运行 Fusion 探针，记录原版行为。框架、样例和压测客人可在无 Photon SDK 环境构建和运行。对象 RPC 调用方向参照 UE |

## 任务与验收门槛

| 里程碑 | 前置 | 实施和交付 | 过关证据 |
| --- | --- | --- | --- |
| M0 构建与基线 | 用户启动 | 核实本地 Cocos2d-x 4 工具链和依赖；建立 CMake 构建入口、无引擎核心测试和空 Cocos 场景；记录 SDK 指纹、已有证据和待证项 | 在干净构建目录生成并启动窗口；独立构建 core；分别记录原版布局探针和既有教学测试 |
| M1 连接与房间 | M0 | 独立连接接口、可控内存后端、本机直连后端；房主监听、建房/加入/开局、席位与身份、超时、结束本局及结束房间 | 两进程在可配置端口建连；验证房间隔离、开局锁员、房主退出与失联；在同一房间再开一局并隔离旧局消息 |
| M2 权威属性复制 | M0；联调依赖 M1 | 字段定义、稳定 ID、布局、编解码、采集 tick 与发送 tick、增量确认、接收应用；输入上行，房主模拟后广播。优先用单个浮点打通 | 两端追踪到输入、房主写值、采集、发送、B 应用；注入最后一次变化丢失、重复和乱序，最终状态收敛；保留与 Fusion 的逐项证据和差异 |
| M3 Cocos Replicator 与首个可玩切片 | M1、M2 | 声明式绑定根与子节点、变换预设、预置对象与注册模板生成/销毁；完成两辆车的输入、权威运动、显示位置插值及 3D 展示物 | 两个真实窗口分别操控车辆；单独观测权威快照和显示位置；测试字段独立变化、2D/3D 变换及实例失效，双方的网络对象 ID 一致 |
| M4 RPC 与互动玩法 | M1、M2；玩法验收依赖 M3 | 房间和对象接收器、方向/权限标记、单向可靠或尽力投递、可靠去重排序；接通门、路障和房间播报 | 玩家通过所属对象请求开门，房主批准后同步门状态或单发拒绝原因；公共门上的越权请求不执行；重传不会重复创建路障；客人观察房主销毁实例 |
| M5 断线续玩 | M1、M3、M4 | 恢复身份和席位、清零旧输入、保留车辆并持续模拟、重连基线与增量衔接、轮次清理 | B 掉线后让房主生成和销毁其他对象、移动车辆，B 恢复同一玩家和同一辆车、得到当前世界并能再驾驶；新玩家、错误凭证、旧包及上局恢复请求均不能接管 |
| M6 同机规模与交付 | M3、M4、M5 | 增加两个真实协议轻量客人；脚本化构建、双窗口启动、四人负载、故障注入、可玩步骤及打包说明 | 建立三条真实客人连接并统计 100 个活动复制对象；核对各端最终对象集合和标记属性；记录运行时长、变化比例、tick、每端流量、CPU、内存、队列与恢复时间；提供复现步骤 |

M1 的传输和 M2 的离线状态算法可并行开发；M2 的字段和对象身份契约稳定后，M3 的引擎绑定和 M4 的 RPC 编解码可独立推进。以 **M3 双窗口能开车** 作为第一次可玩交付，以 **M4 开门和路障可交互** 作为玩法完整节点。先测性能基线；未经确认的数字不充当既定预算。

## 首轮契约与设计依据

以下是实现起点的逻辑字段；各里程碑先用有效和无效输入固定语义，再确定编码布局。

| 契约 | 最少要约定的内容 |
| --- | --- |
| 连接 | 监听/连接、后端端点配置、PeerHandle、投递类别、消息边界、断开原因和连接代次。连接层向上提供能力，Session 独立维护玩家身份。[传输决定](../../docs/decisions/game-transport.md) |
| 房间与恢复 | 加入或恢复请求、房间/局次、稳定 PlayerId、恢复凭证、快照基线、切回可提交输入的阶段，以及拒绝原因。[房间状态与恢复验收](../../docs/specs/room-rejoin.md) |
| 对象和状态 | 场景对象/模板 ID、网络实例身份、字段 ID/类型/精度、定义版本、发送 tick、基线与状态确认。声明式配置描述根/子节点路径、变换预设和自定义字段。[属性规格](../../docs/specs/property-binding.md) |
| 输入与表现 | 房主关联实际发送连接和玩家，输入带序号/局次；持续操控与一次性动作分别约定重复和丢失处理。快照时间、权威值和插值显示值可分别记录 |
| RPC | 作用域、对象或房间身份、方法 ID、允许方向与所属连接、参数定义、投递类别、序号和生命周期。业务回应使用独立 RPC。[RPC 规格与 UE 规则](../../docs/specs/rpc.md) |

**工程默认与研究顺序**：对 API 名、配置语法、默认 tick、输入冗余、量化和插值策略等可调整细节，由执行者先查 Fusion 的对应机制，再按已定优先级参考 UE 和本项目设计。将证据、未知项及采用的默认值分开记录；通过同一输入轨迹和不同网络条件检验。影响已确认玩法、支持平台、产品范围的变化再交用户裁决。

## 如何交付与接续

- 生产代码按 `core/{state,session,transport}/` 与 `engineplatform/cocos2dx/` 归位；可玩样例放 `examples/`，运行工具放 `tools/`，核心/对照/集成测试放 `tests/`。
- M0 建立并记录首条真实构建命令，后续逐项登记核心测试、双窗口、断线恢复和四人压力模式的可复制命令。拟建入口在其存在并跑通后才标为可用。
- 每过一个里程碑，在执行状态中登记改动、命令、退出结果、可玩步骤、未决项和下一项。保持“原版实测、自研实测、双方对照”三个栏位。
- 用户启动后连续推进，完成一项即可进入已满足前置条件的下一项。出现可恢复的构建或测试失败时优先修复、复跑；原版不可测时继续独立的自研验证并标明边界。最终以可玩的双实例和四人真实协议负载均可复现为完成条件。

# 跨引擎联机框架长期任务 · 已确认决定

访谈已收口，实施入口见[完整执行计划](执行计划.md)和[执行状态](执行状态.md)。用户已明确三项能力：节点同步、RPC、房间系统。目标是支持多款引擎，尽可能参照 Fusion。原版证据、自研选择、产品验收遵循[项目工作约定](../../AGENTS.md)。

## 第一轮已确认的产品决定

| 主题 | 用户决定 | 对任务的影响 |
| --- | --- | --- |
| 多引擎 | 每款支持的引擎分别实现同引擎联机即可 | 首发引擎和平台按第五轮决定验收。 |
| Fusion 参照范围 | 底层框架、RPC 和属性同步尽可能与 Fusion 一致，API 可自行设计，交付无需云服务 | 逐项记录底层机制、证据及因房主拓扑产生的差异。 |
| 房间与权威 | 房间管理允许用 TCP；开房玩家担任主机，决定最终状态 | 房主同时承担玩家与权威端角色。 |

## 第二轮已确认的架构决定

| 主题 | 用户决定 | 可验收行为 |
| --- | --- | --- |
| SDK 依赖 | 框架全部自研，最终交付完全独立于 Photon SDK | 在没有安装 Photon SDK 的环境构建并运行房主和客人。运行原版取证探针属于独立研究环境。 |
| 连接路径 | 局域网或已知 IP；房主监听 TCP 管理房间，客人直连房主 | 用房主地址建连、入房、退房。游戏通道见第五轮决定，局域网自动发现单独讨论。 |
| 权威数据流 | 客人只提交输入或动作请求，房主模拟并广播最终属性 | 用客人的油门输入驱动一次房主模拟，客人读到房主算出的车辆属性。客户端预测、回滚属另行讨论的表现机制。 |
| 房主离开 | 主动退房和意外掉线都结束房间 | 正常退出时收到结束事件；失联时收到明确的断线或超时通知并结束本局。超时阈值待定。 |

## 第三轮已确认的节点与入局决定

| 主题 | 用户决定 | 可验收行为 |
| --- | --- | --- |
| 开局后入房 | 从开局到本局结束，关闭新玩家加入 | A、B 开局后，C 尝试加入被拒绝，房间成员保持 A、B。已在局内的 B 仍能收到新对象。已入局成员断线后凭原身份返回，见第七轮。 |
| 节点生命周期 | 场景预置网络节点，加上房主动态生成、销毁的已注册模板 | A 修改预置节点、生成并销毁模板实例，B 在同一局中观察到对应变化；模板或预置节点的子节点属性可按配置复制。 |
| 声明属性 | 优先可配置的 Replicator，提供常见变换预设，支持选取根节点或子节点上的自定义属性 | 测试场景用配置绑定一个根属性、一个子节点属性，分别改变并在 B 验证。各引擎编辑器入口和预设清单待定。 |
| 历史 RPC | 推迟到后续版本再定义历史 RPC 语义 | 首版验收聚焦当前会话的调用与投递；不把事件重放加入完成条件。 |

## 第四轮已确认的 RPC 决定

对象与房间级调用都要支持。对象 RPC 的声明和选路参照 UE。客人之间的远程调用按 Epic 的执行矩阵经房主处理，每个方法单独声明可靠有序或尽力投递。业务反馈通过显式的回应 RPC，最终状态由复制属性表达。房间级接收器映射作为本项目设计单独记录。[RPC 规格与官方依据](../../docs/specs/rpc.md)

## 第五轮已确认的首发范围

- 两层为 `core` 和 `engineplatform`。第一套平台接入是 Cocos2d-x，使用工作区的 4 版源码；正式验收运行两个 Windows x64 Cocos 进程，可移植核心可独立构建。
- 房主、客人都读取声明式配置。Godot 检查器和 Cocos 可视化工具后续再做。
- 传输研究优先级为 Fusion → UE → 上轮选项 1。Fusion Core 已公开 Notify 的三通道设计；本项目采用 TCP 房间 + 自研 UDP 游戏层。输入冗余等尚缺具体证据的问题继续按上述优先级研究。[传输证据和选择](../../docs/decisions/game-transport.md)

## 第六轮已确认的负载、表现与连接约束

- 优先交付可玩的 Windows x64 Cocos 样例。日常验收在一台机器上以房主、客人两个端点通过真实套接字互联；目标负载为含房主的 4 人和 100 个同时参与复制的网络对象。四人同机负载方式见第七轮。
- 同时支持 2D 和 3D 变换。房主游戏逻辑负责物理和权威模拟，客人收到快照后对显示位置插值。本地预测后续再做。
- 当前环境可实测本机互联。地址、监听网卡和端口可配置，以支持局域网或跨设备接入；真实双设备结果待环境具备后记录。RTT、丢包率与性能阈值尚未定标。
- 连接模块独立可替换。TCP 房间 + UDP 游戏流量是首个直连后端；纯 TCP、Steam P2P、自研 P2P 是后续接入方向。[连接边界和验证](../../docs/decisions/game-transport.md)

## 第七轮与重连补充决定

- 可玩样例为俯视小车场：双人驾驶、开门、生成/销毁路障，场内有一个同步的 3D 展示物。
- 日常使用两个 Windows x64 Cocos 进程。压力模式另起两个走真实网络协议的轻量客人，总计一个房主、三个客人，房间内有 100 个同时复制的对象。
- 普通客人掉线时，房主保留身份、玩家数据和名额直到本局结束。清零驾驶输入，车辆留在世界内继续物理模拟；重连后原玩家接管原车并取得当前状态。开局后继续拒绝新玩家。正常结束本局后回原房间等待、开放加入，由房主再开局；房主退出或失联则结束房间。[重连规格](../../docs/specs/room-rejoin.md)
- 用户先审阅完整计划，并自行启动工程任务。启动后连续按里程碑推进，涉及已确认产品范围的变化再询问。

任务分解、依赖与验收以[执行计划](执行计划.md)为准；实际执行与复测入口在[执行状态](执行状态.md)维护。

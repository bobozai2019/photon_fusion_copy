## 房主路由器复核

`192.168.3.1` 的管理页识别为华为路由 AX3 Pro，当前需登录。从 WLAN 通过 SSDP 发现其 UPnP IGD，`GetExternalIPAddress` 返回 HTTP `200` 和 `192.168.1.3`，该地址属于私网。用 `GetSpecificPortMappingEntry` 分别查询 TCP 和 UDP `43263`，两次都返回 UPnP `714 NoSuchEntryInArray`。[UPnP WANIPConnection 规范](https://upnp.org/specs/gw/UPnP-gw-WANIPConnection-v2-Service.pdf) · [私有地址范围](https://www.rfc-editor.org/rfc/rfc1918.html#section-3)

普通 `tracert` 超时。显式绑定 WLAN 后，运行 `ping.exe -4 -S 192.168.3.10 -n 1 -i <TTL> -w 1200 1.1.1.1`，TTL 为 1、2、3 时分别收到来自 `192.168.3.1`、`192.168.1.1`、`100.64.0.1` 的 TTL 超时应答。第三跳属于运营商共享地址范围，该观测不能单独确定上游设备的 WAN IP 或运营商是否做 NAT。`192.168.1.1` 可访问管理登录页，UPnP IGD 和 NAT-PMP 的只读查询均未返回 WAN 地址。[共享地址范围](https://www.rfc-editor.org/rfc/rfc6598.html#section-3)

若上游有可入站的公网 IPv4 且可配置转发，当前拓扑需要将上游 TCP/UDP `43263` 转到 AX3 Pro 的 WAN 地址，再由 AX3 Pro 转到 Windows 房主。登录后可在「更多功能 → 路由器信息」核对 WAN 地址，在「更多功能 → 安全设置 → NAT 服务」选择实际房主设备并设置外部和内部端口 `43263`，协议选 TCP/UDP。本机地址由 DHCP 分配，映射前以路由器显示的地址为准。[华为 WAN 地址说明](https://consumer.huawei.com/cn/support/content/zh-cn00225397/) · [华为端口映射说明](https://consumer.huawei.com/cn/support/content/zh-cn00225381/)

用户处理 Windows 防火墙通知后，读取本地持久规则发现，构建目录里的 `netcode-unity.exe` 有两条启用的 `Public` 入站阻止规则，分别匹配 TCP 和 UDP。先前从临时路径启动的 Player 副本也各自留下了路径对应的规则。读取生效策略仍需管理员权限。后续本机测试复用构建目录，房主公网验收使用固定路径并在首轮前处理冲突的阻止规则。[Windows 防火墙规则优先级](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules)

## 分机采集命令预检

从复制的 Player 目录启动，146 个文件的 SHA-256 均与构建目录相同。用 Windows PowerShell 启动房主、PowerShell 7 启动客人，在本机 WLAN 地址重跑故障轮。首次运行的退出码文件为空；改用 `Start-Process -Wait -PassThru` 后，双端记录实际退出码 `0`，各生成 960×630 的车场截图。两端均有 TCP/UDP 收发，最终均为 5 个对象，摘要 `13210621617771840651`。客人恢复耗时 1,216 ms，UDP 丢弃、复制、乱序合计 `18 / 28 / 25`。

处理防火墙通知后，复用构建目录的 Player 跑完同机 WLAN 故障轮，无需再次交互。双端退出码 `0`，场景摘要均为 `8755909123873240081`，客人恢复耗时 1,266 ms。这些预检的原始数据已随 `out/runs/last-pass/` 轮换，最新原始数据是本机转发的正常轮和故障轮。Release CTest 的 `wire`、`room`、`replication`、`match` 全部通过。`out/` 用量约 1.79 GiB，D 盘可用约 43.60 GiB。

# 公网 IPv4 直连技术验收

2026-11-20 · Windows x64 Mono Player · Unity `6000.4.0f1` (`8cf496087c8f`)

技术验收通过。两个 Unity Player 在本机连接独立的转发入口。TCP 和 UDP 都经过转发，房主收到同一来源 IPv4 和各自独立的来源端口。客人在首次进房和重新建连后均到达 `Ready`。两轮均在真实 Unity 窗口中运行原有玩法剧本。

## 复现

```powershell
python -B tools/verify_public_yard.py
```

客人使用 `--join 127.0.0.2 --port 43263`，房主使用 `--host --bind 127.0.0.1 --port 43263`。转发器在 `127.0.0.2:43263` 接收两种协议，以 `127.0.0.3` 和各自分配的来源端口转发到房主。重连使用新的 TCP 和 UDP 来源端口。转发器只处理本机流量，连接时使用游戏原有的 IPv4 直连后端。两端使用同一份构建。[验收脚本](../../../../examples/tools/verify_public_yard.py) · [Player 构建指纹](../执行状态.md#player-构建指纹)

上表流量单位为字节，恢复耗时包含 1,050 ms 剧本离线窗口。原始连接和重连的房主侧 TCP 来源端口分别为 `51344 → 51346`、`51356 → 51358`，UDP 来源端口分别为 `51043 → 51045`、`61462 → 61464`。每个连接及映射都有双向流量，UDP 的客人本地端口与房主看到的来源端口不同。

两轮均核对房主收到玩家 2 的开门 RPC、客人观察到结果、双方先后收到属性 `0.75` 和 `-0.5`、路障 5 在客端创建后销毁。客人恢复为玩家 2、车辆 2，补齐仍存活的路障 7，离线期间已销毁的路障 6 未在客端出现。Release CTest 的 `wire`、`room`、`replication`、`match` 共 4 项通过。

两轮双端日志、转发统计和客人画面分别保存于 `out/runs/last-pass/normal/` 和 `out/runs/last-pass/fault/`，按项目规则轮换。

## 部署条件

实际公网部署需有可入站的 IPv4，并把同一端口的 TCP 和 UDP 转到房主。房主的防火墙需允许这两种入站流量。直连后端要求来自同一客人的 TCP 和 UDP 在房主侧呈现相同来源 IPv4，来源端口可不同。当前家庭路由器的上游公网入口、规则和实际互联网链路可达性尚未实测。[房主网络复核](../执行状态.md#房主路由器复核) · [分机部署命令](../执行计划.md#实际公网部署命令)

# Unity Windows x64 真实联机验收

2026-11-20 · Unity `6000.4.0f1` · Windows x64 Mono Player · Cocos2d-x 4

第一阶段以两个 Unity Standalone Player 的真实双窗用例为准。两个独立的图形窗口通过本机 IPv4 TCP/UDP 连接。已有脚本在进程内驱动按键对应的车场行为，网络和渲染走正常游戏入口。同次验收还记录了两个轻量客人参与的四人用例。下文 Unity 与 Cocos 混合联机是历史诊断，现行产品支持范围见[同引擎客户端同步](../../../docs/specs/game-session.md#同引擎客户端同步)。

## 复现

```powershell
python -B tools/build.py --unity
python -B tools/verify_yard.py play --platform unity --port 43264 --fault
python -B tools/verify_yard.py play --platform unity --port 43263 --capture
```

已有跨引擎兼容性用例可按下面的命令复现。

```powershell
python -B tools/build.py --unity --cocos
python -B tools/verify_yard.py play --platform unity --guest-platform cocos2dx --port 43261 --fault
python -B tools/verify_yard.py stress --platform unity --guest-platform cocos2dx --port 43262 --seconds 10 --fault
python -B tools/verify_yard.py play --platform cocos2dx --guest-platform unity --port 43260 --capture
```

本机同引擎用例使用 `--unity` 独立构建。生成的 Unity 原生插件依赖 `WS2_32.dll`、`bcrypt.dll` 和 `KERNEL32.dll`。跨引擎用例的本机 Release 另带可选 Steamworks 1.64 后端。此处所有连接使用直连。Steam 登录、P2P 中继和跨设备联机需要单独实测。C++ `wire`、`room`、`replication`、`match` 四项回归通过。

## 运行时判定

- 每对宿主和客人必须有实际窗口及不同进程 ID，且双方最终正常退出。
- 开门请求在房主执行。客人从自己的车发起调用，并收到门状态更新和业务拒绝。`net_input_x` 在断线前以 `0.75` 同步，恢复后以 `-0.5` 同步。
- 客人车场中的在线路障会实际生成与移除。离线时房主先创建再销毁对象 6，留下对象 7。Unity 恢复时生成仍存活的对象 7，保持玩家 2 和车辆 2。
- Unity 根据网格路径 `model` 读回实际信标 GameObject 的位置、三轴旋转和缩放。转动车辆的朝向还与共用模拟的方向向量核对。匹配的状态摘要覆盖对象 ID、模板、所属和所有复制字段。
- 末轮原始日志、指标和 Unity 画面按项目的轮换规则保存在 `out/runs/last-pass`。

## 扩展边界

Unity 的新增代码集中在 C ABI 桥接、C# 节点绑定和场景展示。用同一份车场配置和信标资源即可与 Cocos 联机。房间、传输、RPC、状态复制、恢复票据和固定步模拟直接复用。若后续需要通用 Unity SDK，可独立整理车场专属动作、模板注册和工厂扩展接口。[Unity 接入设计](../../../docs/decisions/unity-platform.md)

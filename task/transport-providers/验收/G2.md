# G2 · Direct 互通与发送出口

对照来自已发布的 Windows x64 Release Core 0.1.0 归档，SHA-256 为 `3e09437389ee31678fd34dde6c74f28c9c30a7ff25f43098c2fc4117fa87a8e6`。候选代码见 `b10f35e`，Core 归档 SHA-256 为 `0de3f6d0db3e700f92bfac4c786926415a4f5cc97f2f7d22302c1f9b5bc1781b`。

| 用例 | 结果 |
| --- | --- |
| 从隔离的 `e8ca53d` 源码重建基线 | CTest 9/9。归档构建标识 `93d65c3c7f39b403`，发布对照包的标识为 `3f89f0ca652f25a1`，互通测试使用原发布归档。 |
| 候选 Core Release | CTest 9/9，覆盖房间、复制、兴趣、对象权威、编解码、房主迁移及 LAN 目录。 |
| 只有 Core 的安装树 | `NETCODE_DIRECT=OFF` 和 `NETCODE_TRANSPORT_HOST=OFF`。带空格的独立消费目录仅链接 `Netcode::Core`。内存双端进房、开局和收敛到 42。 |
| 分批和关闭前排空 | 限额夹具按同一对端提交三条 Game 消息和一条 Control。先接受 1/3，随后重试剩余两条 Game 并发送 Control。释放队列后才关闭，旧字节和顺序一致。 |
| 旧房主＋新客人、新房主＋旧客人 | 各从独立解压的归档编译相同夹具。双方分别接入，客人取得写权、复制 42、完成双向可靠 RPC、断开后凭票接回同一席位。旧／旧及新／新也通过。 |
| 业务字节 | 以旧／旧为对照，每组房主 8 条、初始客人 1 条、接回客人 1 条，包含 Entered、单对象快照及 RPC。按 peer 和消息内容合并重发，统一随机接回密钥、包 tick、对象版本和采样 tick。保留所采消息的通道、顺序和其余字节。三组与旧／旧完全一致。 |
| 基础房间协议 | 另外双向跑了错误房间、锁房、第二轮及失联超时，全部通过。 |
| 现有 Core 消费入口 | `tests/integration/verify_install.py` 通过带空格的迁移安装路径、双进程轮次及超时。故意用 /MD 消费 /MT 包时编译明确报 CRT 不匹配。 |
| Provider 房主自愿接替 | 安装树的 C++ 夹具分别以 TCP 和命名管道打开主连接及备用监听，客户端席位 2 接任为 term 2，恢复最后写入的 42，旧房主退出活动会话。两条链路退出码 0。 |

业务互通日志为 `out/runs/transport/g2-compat.log`，完整角色日志在 `out/tmp/direct-compat/`。对照夹具可用 `tests/transport/verify_direct.py` 指定两份 Core ZIP 复跑。

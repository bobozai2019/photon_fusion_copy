## 构建

以下命令在本 worktree 执行。Windows SDK 用 VS 2026 x64、Release 和静态 CRT。Godot 使用 4.7.1，C++ 绑定为 godot-cpp 4.5-stable，Unity 使用 6000.4.0f1。

```powershell
python -B tools/build.py transport-tcp --package
python -B tools/build.py all --package --cocos-root D:/photon_copy/cocos2d-x-4
python -B tests/integration/verify_install.py out/packages/core-win-x64/current/netcode-core-win-x64.zip
```

独立 Core 用 `cmake -S core`，配置 `NETCODE_DIRECT=OFF` 与 `NETCODE_TRANSPORT_HOST=OFF`，安装后从空 CMake 工程只链接 `Netcode::Core`。独立插件用 `cmake -S network/tcp` 或 `cmake -S network/direct`，将 `NETCODE_TRANSPORT_INCLUDE` 指向 Core SDK 或 `network/api` 的安装 `include`。接口与使用约定见[传输接口](传输接口.md)和[实现决定](../../docs/decisions/transport-provider.md)。

三端消费测试使用 `tests/transport/verify_players.py`。指定候选 `out/packages`、外部 DLL、错误 ABI DLL 和新的 `--work` 路径。Godot 指定控制台编辑器，Unity 指定编辑器，Cocos 指定 CMake 和宿主引擎的 CMake 导出目标。脚本对照安装清单的 SHA，记录 Player 和原生平台哈希、实际 provider 标识及入房、复制、RPC、接回结果。

## 性能输入与发布

`tests/transport/property_transport_matrix.py` 从显式传入的属性探针执行 A/B/C。三个变体使用相同的负载与双方计时窗口。A 使用指定 Direct 基线，B 和 C 使用同一个候选 Godot SDK ZIP，分别选 Direct 与纯 TCP。探针记录双方原始日志、归档 SHA、正确性、步速、P95、可见版本及双方队列统计，并逐格轮换版本执行顺序。

正式计分接续[原计划](改造方案.md#验收与交付)。三端已有地址和端口入口继续采用 Direct。新增 provider 接口默认参数为 `tcp`，新项目模板的默认链路由 G4 签收决定。

代码与摘要随 Git 保存，候选包位于本 worktree 的 `out/packages/*/current`，原始日志位于 `out/runs/transport/` 和各自的 `out/tmp/` 验证目录。验收结束时 `out/` 约 1.75 GiB。Steamworks SDK 未在本工作区提供，Steam 单独构建待其依赖。

## 实施时使用的命令

先在本 worktree 执行 `git rev-parse --show-toplevel`、`git branch --show-current` 和 `git worktree list`。规划完成后的第一份代码交付是 T1 的公共 C 头文件及独立消费者夹具，运行位置设在本 worktree 的 `out/`。

以下为对齐现有 SDK 源码后可复用的 Windows 验证入口。它们是后续验收命令，尚未在规划分支执行。CMake 和第三方引擎源码可以共享只读输入，构建树、安装与归档使用当前 worktree。

```powershell
python -B tools/build.py all --package --cocos-root D:/photon_copy/cocos2d-x-4
python -B tests/integration/verify_install.py out/packages/core-win-x64/current/netcode-core-win-x64.zip
```

三端外部消费在独立的示例副本运行 `tools/verify_sdk_install.py godot`、`tools/verify_sdk_install.py unity`、`tools/verify_cocos_install.py --engine-build <独立的Cocos宿主构建目录>`，均使用 Python。当前示例工具同时校验包路径与锁文件；在副本生成与候选 SHA 匹配的 `sdk-lock.json`，将 `NETCODE_PACKAGES` 指向此 worktree 的 `out/packages`。实施 T4 时在这些用例加入 provider 选择、由启动参数切换同一成品的双次运行和插件 ID 断言。

性能探针已有显式 ZIP 参数。下面是一房的原生稀疏冒烟入口；实施 T5 时将选定驱动接入测试配置。正式计分按总纲串行跑全矩阵，A、B、C 候选分别归档，记录加载的包路径和哈希。使用同一性能计划版本对齐测量窗口与环境。

```powershell
python -B research/fusion/probes/property_scale.py native 5000 --workload sparse --sdk-zip out/packages/godot-win-x64/current/netcode-godot-win-x64.zip
```

证据写入本任务的 `验收/`：G1 接口与 TCP，G2 旧端互通，G3 三端外部消费，G4 属性同步矩阵。每条记录带基线与候选 SHA、角色、provider 标识、实际命令、退出码和失败格。规划阶段只做工作树、资料与归档指纹核对。
